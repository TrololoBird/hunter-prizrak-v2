## 1. Форма подачи зоны: диапазон + ключевой уровень внутри = наша модель

Каждая ТВХ подаётся как «Диапазон интереса: X–Y», часто с ключевыми уровнями внутри:

* id 7660 (UAI, блок под подписью «Разбор зон интереса #UAI» — пост мульти-активный):
  «🔴 Шорт : 1,65–1,9 ПОК = 1,7500» — автор сам пишет ПОК зоны,
  и он в 40% от низа диапазона, НЕ в центре. Согласуется с пиксельным замером
  рисунков курса (ПОК на 36%/64% высоты зоны, ответ course-reader 2026-08-18);
* id 7766 (ATOM): «Основные шорт-уровни: 1,8 и 1,98 (ПОК1 и ПОК2 недельной базы)»;
* id 7733 (HMSTR): зона «0,00016 -0,00017 (общий ПОК накопления)»;
* id 7736 (AERO): «Лонг зона : 0,073–0,108. Ключевой уровень : 0,088».

Это прямое корпусное подтверждение модели `ZoneSpec` (zone_lo–zone_hi + price=ПОК)
и вчерашней правки карты: края диапазона — по зонам, ПОК — точка внутри.

⚠ Термин «диапазон интереса» — корпусный, в тексте курса его нет (греп по PDF,
ответ course-reader 2026-08-18). Ссылаться на него как на термин курса нельзя.

## 4. Режим входа — часть зоны, и у нас для этого уже есть поле

Автор различает: «лимитки» (вход отложкой заранее), «по факту» (только по
подтверждению реакции), «под наблюдение». Жёлтая пометка зоны у него систематически
означает «по факту/наблюдение», зелёная и красная — рабочие лонг/шорт зоны, 🎯 —
«снайпер» на прокол. Примеры: id 7654 «эту зону по прежнему рассматриваю как зону , которую можем
проколоть без реакции - поэтому работать с ней лучше всего по факту» (пробел перед
запятой — авторский);
id 7752 «Заранее просто ставить лимиты выше мне менее интересно».
`ZoneSpec.entry_rule` получает корпусный референт; чем заполнять — вопрос этапа
правил входа, не этой смены.

1. Строка-сводка ширины зон в `hunter check` (диагностика, расчёт не тронут;

2. этот документ + три зонда с живыми выводами в evidence (плоский текст, ширины,
