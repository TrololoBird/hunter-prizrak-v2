# Факты о Binance USDⓈ-M — замеры 2026-08-03

Всё ниже измерено на живой бирже или взято из документации со ссылкой. FOUNDATION.md §0, §7.3.

## 1. Предел `limit` у свечей — 1500

| limit | ответ |
|---|---|
| 1500 | HTTP 200, баров 1500 |
| 1501 | HTTP 400, `{"code":-1130,"msg":"Data sent for parameter 'limit' is not valid."}` |

```bash
uv run python -c "
import json, urllib.request as u
for lim in (1500, 1501):
    try:
        with u.urlopen(f'https://fapi.binance.com/fapi/v1/klines?symbol=BTCUSDT&interval=1h&limit={lim}') as r:
            print(lim, r.status, len(json.load(r)))
    except Exception as e: print(lim, getattr(e,'code',''), e.read().decode()[:120])
"
```

**⚠ ccxt режет выдачу до 1000 сам.** `fetch_ohlcv(..., limit=1500)` и `limit=1501` оба
вернули 1000 баров. То есть предел биржи и предел клиента — разные числа, и полагаться
на первый через ccxt нельзя. В коде: `KLINES_MAX_LIMIT=1500`, `CCXT_EFFECTIVE_LIMIT=1000`.

Глубина, которую даёт один запрос ccxt (замер на BTC/USDT:USDT):

|---|---|---|
| 1w | 362 | с 2019-09-02 (вся история контракта) |

| 5m | 1000 | 3.5 суток |

## 2. Сетка баров

Недельный бар открывается в понедельник 00:00 UTC. Замер: у всех недельных баров
`open_ms % 604800000 == 345600000` (= 4 суток), потому что эпоха UTC приходится на четверг.
У остальных ТФ сдвига нет.

Это не комментарий, а рабочая константа `bars.py::GRID_ANCHOR_MS`; соблюдение сетки
проверяется на каждом принятом баре (`bars.py::on_grid`) и печатается в приёмке.

## 3. История сделок по REST — только 24 часа

Документация Binance, Compressed/Aggregate Trades List (`/fapi/v1/aggTrades`):
максимум `limit` 1000, по умолчанию 500, и дословно — «support querying futures trade
histories that are not older than 24 hours».

**Следствие:** сверка с разборами автора (даты 2026-07-11…07-27) по REST невозможна
в принципе. Историю даёт только архив, см. §4.

## 4. Публичный архив `data.binance.vision` — есть, с контрольными суммами

```bash
uv run python -c "
import urllib.request as u, hashlib
base='https://data.binance.vision/data/futures/um/daily/aggTrades/BTCUSDT/BTCUSDT-aggTrades-2026-08-01'
cs=u.urlopen(base+'.zip.CHECKSUM').read().decode().split()[0]
blob=u.urlopen(base+'.zip').read()
print('байт', len(blob), '| sha256 совпал:', hashlib.sha256(blob).hexdigest()==cs)
"
```

Замер на `BTCUSDT-aggTrades-2026-08-01`:

| | |
|---|---|
| zip | 5 049 749 байт |
| CSV внутри | 26 515 205 байт |
| строк (сделок) | 399 219 |
| `.CHECKSUM` | есть, sha256 **совпал** |

Колонки CSV (из заголовка файла): `agg_trade_id, price, quantity, first_trade_id,
last_trade_id, transact_time, is_buyer_maker`.

Целостность проверяется в коде: `archive.py` функция fetch_agg_trades_day ⟨механизм удалён 2026-08-11, см. archive-removed-2026-08-11.md⟩ возвращает `NotReady`,
если суммы нет или она не сошлась, — а не молча отдаёт непроверенный файл (§4.3).

## 5. Часы

Сдвиг «биржа минус локальные» на этой машине, замер по схеме NTP
(`сдвиг = server − (t_до + t_после)/2`, берётся замер с наименьшим rtt из 5):

| прогон | сдвиг | rtt | уход за 400 с |
|---|---|---|---|
| 1 (3 символа) | −77 мс | 333 мс | +8 мс за 70 с |
| 2 (27 символов) | −60 мс | 331 мс | см. протокол прогона |

Порядок величины — десятки миллисекунд, а не десятки секунд, как в предыдущей
реализации (там было 43,4 с). Неопределённость самого замера ±rtt/2 ≈ ±165 мс, то есть
**она больше измеренного сдвига** — это надо знать прежде, чем считать сдвиг значимым.

## Что осталось непроверенным

- Период пересчёта сдвига не назначен: за 70 с уход +8 мс, но одной точки мало, чтобы
  назвать скорость ухода. Пока часы сводятся при старте и перемеряются в конце прогона.
- Предел 1500 проверен только на `1h`. На других ТФ не проверялся.
- Архив проверен на одном символе за одни сутки. Полнота архива за длительный период
  и наличие дыр в нём не проверялись.
