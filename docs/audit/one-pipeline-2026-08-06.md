# Один конвейер: карточка и леджер из одного расчёта

**Дата:** 2026-08-06. **Решение владельца:** «один конвейер: карточка и леджер из одного
расчёта». **Что было до:** расчёта как места не существовало.

---

## 1. Как нашлось

Вопрос владельца был буквальный: **определились ли мы, что в какой последовательности
вызывается.** Ответа не было ни в одном документе и ни в одном гейте, поэтому граф
вызовов внутри `hunter` вытащен разбором синтаксического дерева — с учётом
переименованных импортов, иначе `from .stop_volume import classify as classify_stop_volume`
пропадает из графа.

Нашлось четыре вещи, и все проверены исполнением, а не чтением.

### 1.1. Решение считалось ДВАЖДЫ

Тройка `priority.resolve` → `priority.agreement` → `geometry.build_setup` вызывалась
независимо в двух местах: в карточке и в отборе эмиссий. Общего кода — нет.

| место | что делало |
|---|---|
| `card.py:153-155` | обход ВСЕХ размеченных уровней, для каждого — приоритет, согласие, геометрия |
| `emit.py:77-79` | обход тех же уровней с фильтром, для прошедших — то же самое |

### 1.2. Фильтр эмиссии стоял ТОЛЬКО в одном из двух

`emit.select` брал `state is ACTIVE and limit_orders_allowed`. `card.render` не фильтровал
ничего. Замер на сохранённых кадрах прогона `a1` (3 символа, горизонт 5 суток):

| символ | карточка печатала геометрию | леджер эмитировал |
|---|---:|---:|
| BCH/USDT:USDT | 15 | 6 |
| BTC/USDT:USDT | 43 | 15 |
| ETH/USDT:USDT | 36 | 12 |
| **итого** | **94** | **33 (35.1%)** |

Состояния уровней: `active` 33, `flipped` 31, `worked_off` 30. То есть **на двух карточных
сетапах из трёх стояла полная геометрия — стоп, лестница, цели, РР — для уровня, который
система не торгует.**

### 1.3. У флипнутых уровней геометрия была ПРОТИВОПОЛОЖНА курсу

Хуже, чем лишняя строка. Для 31 флипнутого уровня `build_setup` строил вход, стоп и цели
для ИСХОДНОЙ стороны, тогда как стр. 43 говорит: «Уровень лонг/шорт менятся для нас на
противоположный», а вход — «По возврату цены на ретест уровня». Карточка показывала
сделку в сторону, обратную той, что велит брать курс.

Собственный код проекта это знал: `levels.EntryRule.RETEST_FLIPPED` заведён именно под
стр. 43 и печатался строкой выше. Знание было, применения не было.

### 1.4. Разбор ряда считался по два-три раза на ТФ

`swings.detect` и `accumulation.detect` звались в `card.render`, внутри
`levels.build_all` и ещё раз в `run.record` (для трендов). Одни и те же бары, один и тот
же ответ, три вызова.

---

## 2. Что сделано

Появился `src/hunter/engine.py` — **единственное место, где считается сигнал**. Порядок
шагов теперь записан в одной функции `engine.decide`, а не выведен из чтения двух модулей:

```
ряды → свинги → структуры → уровни (ПОК) → судьба уровня → приоритет → геометрия
```

Каждый шаг зовётся ровно один раз. Карточка и леджер — **два потребителя одного
результата**, и ни один из них больше ничего не считает.

| было | стало |
|---|---|
| `card.render(symbol, series, trades, tfs, prebuilt)` — считала сама | `card.render(decision, series)` — только печатает |
| `run.record(..., sources, built)` — считала сама | `run.record(..., decided)` — только пишет |
| `run.build_levels_once` — один раз только УРОВНИ | `run.decide_once` — один раз ВСЁ решение |
| `emit.select(mapped, trends)` — второй обход пула | `emit.hold_reason(status)` — правило от одного статуса |
| `levels.build_all(..., tfs)` — звала `swings`/`accumulation` внутри | `levels.build_all(..., tfs, scans)` — разбор подаётся готовым |

`SymbolDecision.emissions` — **проекция** решений, а не второй расчёт: выбирается
подмножество уже принятых решений, и разойтись с карточкой ему нечем.

**Геометрия строится только там, где есть эмиссия.** Уровень, который система не торгует,
получает названную причину (`Decision.hold`) вместо стопа с целями: печатать геометрию
сделки, которая не будет взята, — это печатать сигнал, которого нет (§4.3).

## 3. Предъявление по §10.6: дифф повтора

Кадры прогона `a1` не тронуты, пересчитаны новым кодом.

```bash
uv run python -m hunter replay --run-id a1 --diff
```

| символ | строк было | стало |
|---|---:|---:|
| BCH/USDT:USDT | 186 | 164 |
| BTC/USDT:USDT | 465 | 312 |
| ETH/USDT:USDT | 377 | 260 |

Состав диффа — и он **строго вычитающий**:

| что | строк |
|---|---:|
| ДОБАВЛЕНО «СДЕЛКИ НЕТ: причина» | **61** |
| убрано «стоп …» | 61 |
| убрано «РР … до первой цели» | 61 |
| убрано «цель …» и «промежуточная …» | 220 |
| убрано «лестница …» | 3 |
| убрано «целей нет» | 7 |
| **изменено строк геометрии у эмитируемых уровней** | **0** |

Последняя строка — главная. Добавленных строк с геометрией в диффе НЕТ ни одной: у всех
33 эмитируемых уровней стоп, лестница, цели и РР совпали побитово. Правка убрала то, что
система никогда не торговала, и не тронула то, что торгует.

61 = 94 − 33, то есть ровно те уровни, для которых геометрия печаталась зря.

Сверка после правки:

```bash
uv run python -c "
from hunter import archive, engine, store
from hunter.models import NotReady
for d in store.saved_symbols('a1'):
    sym, tick, bucket = store.read_meta('a1', d)
    tfs = store.saved_timeframes('a1', d)
    series = {tf: store.read_bars('a1', d, tf) for tf in tfs}
    tr = store.read_binned_trades('a1', d, tick, bucket, sym)
    src = archive.WindowSource(sym, sym.split(':')[0].replace('/',''), tick,
        live=None if isinstance(tr, NotReady) else tr, cache_dir=store.archive_dir('a1', d))
    dec = engine.decide(sym, series, src, tfs)
    print(sym, len(dec.decisions), sum(1 for x in dec.decisions if x.setup), len(dec.emissions))
"
```

Результат: решений 94, с геометрией 33, эмиссий 33 — **сошлось у всех трёх символов**.
Исходы отбора: эмитируется 33, отработан на первое касание 30, пробит и флипнут 31.

## 4. Продюсеры без потребителя

Тем же разбором графа найдено **десять публичных функций, которые не зовёт никто**. Это
не побочная находка: одна из них — причина, по которой предыдущее предложение агента
(«собрать оракул для ATR по §8 этап 2») было бессмысленным.

| функция | замечание |
|---|---|
| **`indicators.atr`** | ATR — ПЕРВЫЙ примитив этапа 2 по §8. Не вызывается ниоткуда; стоп строится не на нём. Сверять его с эталоном значило бы сверять неисполняемый код |
| **`clock.is_stale`**, `clock.is_synced` | написаны 06.08 под находку Д-5 и не спрашиваются нигде: служба может работать на часах, просроченных на час, и не заметить |
| `admission.check`, `admission.available`, `admission.strictest_requirement` | §2.9 считается другими функциями того же модуля |
| `archive.histogram_from_window` | окно профиля строит `WindowSource.window` |
| `levels.first_test_index` | «первое касание» по стр. 25 нигде не спрашивается |
| `priority.works_on` | приоритет считается через `resolve` |
| `indicators.macd_signal` | карточка печатает `macd_line`, сигнальную линию — нет |

Список получен разбором дерева, а не чтением, и ни одна из этих функций правкой не
тронута: сначала решение владельца, что с ними делать (§0 — подключить или удалить с
записью решения), потом правка.

## 5. Что осталось незамеренным

⚠ Оговорки по §7.6, а не список работ.

1. **Число 94/33 получено на трёх символах и одном прогоне.** Доля 35% — свойство этой
   выборки, а не константа метода. Направление находки от выборки не зависит: фильтр в
   карточке отсутствовал полностью.
2. **Изменение карточки владельцу не показано на живом прогоне** — предъявлен дифф на
   сохранённых кадрах. Живой прогон даёт тот же текст по построению (карточка — чистая
   функция кадров), но это довод, а не замер.
3. **Стоимость расчёта после правки не перемеряна.** Геометрия для 61 уровня из 94 больше
   не строится, то есть цикл обязан стать дешевле, — но насколько, не замерено.
4. **Гейта, запрещающего второй обход пула, нет.** Сейчас единственность конвейера держится
   на том, что `card.render` принимает готовое решение и не имеет доступа к `levels`. Это
   структурная преграда, а не проверка: новый потребитель может импортировать `levels`
   сам, и никто не заметит.
