# MACD у TA-Lib не равен разности его же EMA — замер 2026-08-03

## Что проверялось

Скалярная реализация MACD по опубликованным формулам разошлась с `polars_talib`
на первых ~160 барах. Вопрос: чья затравка отличается.

Три источника описывают MACD одинаково — как разность двух EMA:

* Wikipedia, MACD: «MACD line = EMA12 − EMA26; Signal line = EMA9(MACD line)»
* StockCharts ChartSchool: «MACD Line: (12-day EMA - 26-day EMA)»
* TradingView, справка: «MACD = Fast MA − Slow MA»

Затравку EMA явно задаёт StockCharts: «a simple moving average is used as the previous
period's EMA in the first calculation». Именно так реализовано в проекте, и отдельная
`ema200` совпала с библиотекой до **4.3e-15**.

## Результат

Сравнение MACD библиотеки с разностью **её собственных** `ema(12)` и `ema(26)`:

| бар | ema12 − ema26 | macd библиотеки | разница |
|---|---|---|---|
| 33 | 586.80062827 | 623.42039739 | **3.66e+01** |
| 60 | −77.24784593 | −76.84527020 | 4.03e−01 |
| 100 | 76.42789364 | 76.42839809 | 5.04e−04 |
| 161 | 75.33675000 | 75.33675002 | 1.89e−08 |
| 300 | 53.81356638 | 53.81356638 | **0.00e+00** |

Сравнено 466 точек, худшее относительное расхождение **5.874e-02**, первое за порогом
1e-9 — на баре 33.

## Вывод

**Это внутренняя несогласованность TA-Lib, а не расхождение с проектным кодом.**
`ema()` библиотеки затравливается простым средним, как написано в источниках, но
`macd()` использует внутри другую затравку. К бару ~300 разница исчезает полностью.

Практическое следствие: значение MACD из `polars_talib` на истории короче ~162 баров
специфично для библиотеки, а не каноническое. По §0 такое значение внешнего референта
не имеет, поэтому в `hunter/admission.py` MACD объявлен каноничным с 162-го бара.

## Решение и известное расхождение

Решение владельца 2026-08-03: **считать MACD как разность собственных EMA**
(`hunter/indicators.py::macd_line`). Библиотека, противоречащая своим же EMA, неправа
по определению, которое дают все три источника.

Расхождение проектного MACD с библиотечным `macd()` зафиксировано как известное число:

| бар | наш MACD | macd() библиотеки | отн. расхождение |
|---|---|---|---|
| 33 | 586.80062827 | 623.42039739 | 5.874e-02 |
| 40 | 460.55866185 | 471.93129243 | 2.410e-02 |
| 60 | −77.24784593 | −76.84527020 | 5.211e-03 |
| 100 | 76.42789364 | 76.42839809 | 6.600e-06 |
| 161 | 75.33675000 | 75.33675002 | 2.514e-10 |
| 300 | 53.81356638 | 53.81356638 | 0.000e+00 |

Сравнено 466 точек, за порогом 1e-9 — 125, последняя на баре 160.

**Снятое требование.** Порог «MACD каноничен с 162-го бара» был свойством библиотеки,
а не величины. После перехода на определение он стал свойством EMA26 — **26 баров**.
Сверка проектного MACD с формулой: расхождение **8.301e-12** на 474 точках, затравка
подтверждена.

## Команда воспроизведения

```bash
uv run python -c "
import polars as pl, polars_talib as plta
df = pl.read_parquet('docs/audit/reference-slice/BTCUSDT-1h-500.parquet')
o = df.select(plta.ema(pl.col('close'),timeperiod=12).alias('e12'),
              plta.ema(pl.col('close'),timeperiod=26).alias('e26'),
              plta.macd(pl.col('close'),fastperiod=12,slowperiod=26,signalperiod=9).struct.field('macd').alias('m'))
for k in (33,60,100,161,300):
    print(k, o['e12'][k]-o['e26'][k], o['m'][k])
"
```
