## (а) Раздел «Проверено и НАРУШЕНИЙ НЕТ»

Отрицательный результат опасен тем, что «ноль» получается и когда искать нечего, и когда
искать нечем. Я взял три строки и проверял их СВОИМ способом.

### а.1 §2.9: влияют ли индикаторы на эмиссию — проверено ИСПОЛНЕНИЕМ, а не грепом

Метод аудита — трассировка и греп. Метод даёт гипотезу; я проверил её прогоном.
`hunter.indicators` подменяется В ПАМЯТИ, после чего `engine.decide` считается заново на
тех же сохранённых кадрах:

```bash
# полный текст зонда: см. блок ниже, кладётся во временный каталог, репозиторий не правится
uv run python - <<'PY'
import sys; sys.path.insert(0, "src")
from hunter import archive, card, engine, indicators, store
# rsi/ema/macd_line/bbands_* заменяются на (x*1.7), (-x) и на чистый NaN;
# сравниваются множество эмиссий, тексты hold и ТЕКСТ КАРТОЧКИ
PY
```

Результат на 9 символах трёх прогонов (`a1`, `conf`, `d4`), 39 эмиссий в базовом расчёте:

| подмена | эмиссии | тексты `hold` | карточка |
|---|---|---|---|
| ×1.7 и смена знака MACD | те же во всех 9 | те же во всех 9 | изменилась во всех 9 |
| все величины → NaN | те же во всех 9 | те же во всех 9 | изменилась во всех 9 |

Всего 18 подмен: **эмиссию изменили 0, `hold` изменили 0, карточку изменили 18.**
Последняя строка — контроль: если бы подмена не доходила до кода, не изменилась бы и
карточка, и «влияния нет» было бы свойством пробника.

Обходного пути от `engine.decide` до `emit.hold_reason` нет и по чтению: `hold` берётся
из `LevelStatus`, тот — из `levels.status` (`first_breach` + `first_test_index`),
`mapped` — из `levels.build_all` (профиль объёма, накопления, стоповый объём, пробой).
Ни один из этих модулей `indicators`/`factors` не импортирует; греп по
`plta|polars_talib|talib` вне indicators.py даёт только строки комментариев.

Проверены и два кандидата в обходной путь, которых в отчёте нет:

* **`admission`** — требования к истории заданы величинами §2.9 (`ema200` = 200 баров), и
  если бы ими фильтровалась вселенная, индикаторы решали бы, будет ли сигнал. Не
  фильтруется: `admits()` зовётся только из диагностической подкоманды `hunter admission`,
  `strictest_requirement()` — только из check.py. Ни то, ни другое в расчёт не входит.
* **`config/universe.toml`** — ключи `bars_per_timeframe = 1000` и
  `admission_required_bars = 200` не читает НИКТО: `config.load_universe` берёт из файла
  только `symbols` и `timeframes`. Глубина посева задаётся умолчанием CLI
  `--seed-limit 500`. Это не нарушение §2.9, но это решение владельца, записанное в
  конфиг и не исполняемое кодом; в реестре находок его нет.

**Вывод: строка отчёта верна, и теперь она подтверждена исполнением с пройденным
контролем фальсифицируемости.**

### Репро М-06 не воспроизводится

```bash
bash docs/audit/repro/M-06.sh; echo "EXIT=$?"
```

→ `EXIT=1`, «ИТОГ: НЕ ВОСПРОИЗВЕЛОСЬ». Причина не в гейтах:

```bash
which python                 # /c/Users/…/AppData/Local/Microsoft/WindowsApps/python
python --version             # печатает «Python» и выходит с кодом 0
printf 'print("STDIN-OK")\n' | python -   # печатает «Python», кода 0, скрипт НЕ исполнен
```

`python` на машине владельца — заглушка Microsoft Store. Скрипт подсаживает нарушение
через `python - <<'PY'`, то есть подсадка НЕ ПРОИСХОДИТ, и гейты гоняются по чистому
дереву. Сторож внутри подсадки (`assert old in s, 'тело rsi изменилось — пробник надо
переписать'`) не исполняется никогда. Здесь скрипт упал громко, потому что ждал единицу;
но раздел «КОНТРОЛЬ: на чистом дереве все три зелёные» прошёл по НЕВЕРНОЙ причине — и это
форма дефекта, которую проект называет своей: печать проверки без самой проверки.
Лечение — одна замена `python -` на `uv run python -`, как во всех остальных командах

### 2. Условие печати: сводка исчезает вместе с блоком

Сводка стоит ВНУТРИ `if d.unbuilt:`. Проверено на 51 сохранённом символе-прогоне:

* **на реальных данных сводка печатается всегда**: символов с пустым `unbuilt` — 0 из 51;
* **но она исчезает целиком, если отказов нет.** Контроль: то же решение с
  `unbuilt=()` — сводка пропадает у всех 12 проверенных символов. Перекос при этом не
  меняется: строки «1Н 0 из 11» просто больше нет. То есть случай «структур на старшем ТФ
  не нашлось вовсе, а младшие построились полностью» даёт максимальный перекос и НОЛЬ
  сводки. На корпусе он не встретился — это дыра латентная, не наблюдённая;
* **вторая дыра наблюдена в живых данных.** ТФ с нулём закрытых структур выбрасывается
  из сводки (`if not total: continue`). `weight/BCH` и `conf/BCH`: 15м имеет 0 структур,
  и строки 15м в сводке НЕТ. Оператор видит сводку из пяти ТФ и не может отличить «15м
  нечего было строить» от «15м потерялся».

### 3. Числа сводки верны

Тождество `len(scan.closed) == построено + не построено` проверено на 51 символе × 6 ТФ:
**расхождений 0.** Знаменатель выбран правильно: `levels.build_all` обходит РОВНО
`scan.closed` и на каждую структуру кладёт либо уровень, либо `Unbuilt`;
`levels.map_levels` отбрасывает только уровни, чьего ряда нет в кадрах, а таких по
построению не бывает.

Контроль фальсифицируемости: различных строк сводки на корпусе — **47**, то есть прибор
не заперт в одном ответе. Примеры настоящих карточек:

```

           4ч 14 из 28 (50%)  1Д 2 из 21 (10%)     1Н 0 из 11 (0%)
last/BCH   5м 0 из 3 (0%) … 1Н 0 из 6 (0%)          ← карта пуста целиком
weight/BCH 5м 0 из 7 (0%) … 1Н 0 из 8 (0%)          ← 15м в сводке ОТСУТСТВУЕТ
```

Перекос, ради которого сводка и заводилась, на живых кадрах системы виден отчётливее, чем
в замере R-01: **1Н даёт 0 уровней в 51 случае из 51**, 1Д — от 0% до 17%.

### Что я пытался опровергнуть и НЕ смог

**Гипотеза 1: «29.1% — артефакт ширины строки».** Прибор А возвращает ЦЕНТР выигравшей

| N строк | совпало (критерий автора) | потолок при ИДЕАЛЬНОМ согласии |
|---:|---:|---:|
| 24 | 29.1% | **86.5%** |
| 50 | 28.6% | 99.1% |
| 100 | 37.7% | 100.0% |
| 200 | 49.1% | 100.0% |

**Гипотеза 2: «доля занижена перекосом по ТФ» (81% замеров лежат на 5м–1ч).** Разбивка

**Гипотеза 4: «у нуля другой объём выборки, и проценты несопоставимы».** Проверено:

### Что подтвердилось: вывод верен, но КОНТРОЛЬ К-2 доказательством не является

**Нуль автора — не нуль, а перенос профиля.** `rotated()` — циклический сдвиг на половину
длины. Он сохраняет ФОРМУ профиля и переносит пик целиком; оба прибора после этого
сдвигаются вместе, и согласие между ними обязано сохраниться. Измерил прямо: сдвиг ПОК
прибора П после поворота — медиана **3089** позиций при медиане **6178** занятых бинов,
то есть ровно половина длины, детерминированно. Это перенос, а не разрыв связи цены с
объёмом.

Довод автора «случайность запрещена §10.3» выбор поворота не оправдывает: перестановка с
фиксированной затравкой так же детерминирована и воспроизводима.

Настоящий нуль — перестановка объёмов по занятым ценам (затравка 20260807):

| N | настоящий | нуль автора (поворот) | нуль QA (перестановка) |
|---:|---:|---:|---:|
| 24 | 29.1% | 26.3% | **40.6%** |
| 50 | 28.6% | 30.3% | **48.6%** |
| 100 | 37.7% | 39.4% | **59.4%** |
| 200 | 49.1% | 48.6% | **66.3%** |

Нуль автора идёт вплотную к настоящему и повторяет его рост по N — подпись нуля, который
воспроизводит измеряемый механизм, а не разрушает его. На перестановочном нуле согласие
ВЫШЕ настоящего на 11–22 пункта. Оговорюсь честно: перестановочный нуль тоже не идеален —
объёмы сделок тяжелохвостые, одна крупная сделка после перемешивания задаёт пик обоим
приборам сразу, и потому баня получается завышенной. Вывод, который держится на обоих
нулях, один: **доля совпадений — свойство формы профиля, а не находка настоящего пика**,
и «не лучше нуля» из К-2 в его нынешнем виде не следует.
