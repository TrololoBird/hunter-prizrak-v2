# Архитектурный дефект: карта уровней не могла появиться никогда

Дата: 2026-08-04. Нашёл владелец — рассуждением о методе, не о коде.

## Как выглядело

Живой прогон записал **0 сигналов**. Я объяснил это тем, что за 120 с собрано мало сделок,
и объяснение было верным по букве и негодным по существу — потому что скрывало, что уровней
не бывает НИКОГДА, а не «мало в этот раз».

Вопрос владельца: «мы же строим карту уровней и зон входа на основе ИСТОРИЧЕСКИХ свечей…
то есть по твоей логике было ноль зон лонга или шорта?»

## Замер

Прогон 3 символа, 120 с:

| символ | структур найдено | уровней построено |
|---|---|---|
| BCH | 60 | **0** |
| BTC | 75 | **0** |
| ETH | 65 | **0** |

**200 структур, ноль уровней.** Зон было полно; отказывал шаг «структура → уровень».

## Причина — моя, архитектурная

Профиль объёма по стр. 26 натягивается на бары структуры. Структуры лежат в ИСТОРИИ —
за 500-1000 баров назад. А я привязал профиль ТОЛЬКО к живому потоку сделок, который
покрывает длительность прогона. Пересечение почти всегда пусто, поэтому уровней не бывает
ни при каком рынке.

Задача 1.6 построила бэкфилл сделок из суточных архивов (`archive.py`), и он **не был
подключён к прогону**. Инструмент существовал, путь к нему — нет.

## Исправление

`run.backfill_trades` доливает суточные архивы биржи под окна структур перед сборкой
карточки. Глубина ограничена `--trade-days` (по умолчанию 3): суточный файл BTC — 15.5 МБ
и 1.26 млн сделок, а структура на 1Н тянется на годы. Непокрытые окна остаются `NotReady`
с названной причиной (§4.3), а не заполняются приблизительным профилем.

## Результат после исправления

Прогон 2 символа, 60 с, `--trade-days 3`:

| | было | стало |
|---|---|---|
| уровней BTC | 0 | **7** |
| уровней ETH | 0 | **10** |
| сигналов в леджере | 0 | **3** |

## Что осталось непроверенным

- **Все построенные уровни — на 5м.** Трёх суток архива хватает только на окна младшего
  ТФ; структуры 1ч и старше остаются без уровня (67 и 55 отказов). Сколько суток нужно
  под 4ч и 1Д — НЕ мерилось, как и цена такого архива по объёму и времени.
- Исходов записано 0: все три сигнала открыты либо вход не состоялся. Ветка «живой прогон
  → закрытый исход» по-прежнему проверена только на архивном зонде.
- Величина `--trade-days 3` — не замер, а бюджет по объёму. Чем её обосновать, кроме
  размера файлов, пока нечем.

## Урок

Ноль был объяснён правдоподобно и не был проверен на вопрос «а может ли это быть НЕ ноль
в принципе». Правило из `CLAUDE.md` («число не докладывается, пока не проверено, что оно
могло быть другим») я применил к детекторам, но не применил к нулю, у которого уже было
объяснение. **Наличие объяснения не заменяет проверку — оно её маскирует.**

## Как воспроизвести (§7.3)

```bash
uv run python -m hunter run --symbols 3 --seconds 120 --trade-days 0
uv run python -m hunter run --symbols 3 --seconds 120 --trade-days 3
```

Первая команда воспроизводит дефект (уровней 0), вторая — исправление.
