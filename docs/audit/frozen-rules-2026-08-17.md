# Сверка «закреплённых правил» с тем, что они на самом деле делают

**Дата:** 2026-08-17. **Повод:** владелец усомнился в утверждении «корпус ∪ топ-12 по
обороту, замеренным 2026-08-03» и потребовал проверить ВСЕ закреплённые правила.

**Сомнение подтвердилось.** Правило отбора не описывает состав файла спустя две недели, и
это не старение данных, а свойство самого правила. Кроме того найдены два мёртвых
объявления, одно из которых я внёс сам сутки назад.

---

## 1. Первое: моя собственная ошибка в этой же проверке

Первый прогон сверки печатал «топ-12 сегодня: BTC, ETH, **BTC, ETH**, SOL…» — с
дубликатами. Причина не в бирже: **я не воспроизвёл фильтр зонда отбора**, который берёт
только рынки с `settle == USDT and quote == USDT`, и в рейтинг попали ещё и
USDC-маржинальные рынки тех же монет. Все числа ниже сняты уже правильным фильтром.

Отсюда общее: сверка правила обязана исполнять ЕГО фильтр, а не похожий.

## 2. Правило «топ-12 по обороту» не держится: 4 из 10 за 14 суток

Замер (биржевое время 2026-08-17T03:52Z), кандидатов — 524 крипто-бессрочных с расчётом
в USDT и известным оборотом:

| символ файла | место сегодня | оборот 24ч, $ | листинг |
|---|---|---|---|
| SOL | 3 | 725 267 236 | 2020-09-14 |
| XRP | 6 | 289 458 920 | 2020-01-06 |
| HYPE | 8 | 252 381 077 | 2025-05-30 |
| ZEC | 12 | 198 182 782 | 2020-02-05 |
| BNB | **14** | 164 762 883 | 2020-02-10 |
| DOGE | **17** | 126 547 356 | 2020-07-10 |
| ADA | **25** | 77 023 143 | 2020-01-31 |
| BICO | **27** | 61 653 552 | 2023-09-28 |
| BLESS | **93** | 13 359 479 | 2025-09-23 |
| 1000RATS | **169** | 4 122 616 | 2023-12-15 |

**В топ-12 осталось 4 из 10.** Крайний случай — 1000RATS: сегодня 4,1 млн против ~200 млн,
которые нужны для входа в двенадцатку, то есть в полсотни раз меньше. Ни один из десяти
не был свежим листингом на момент отбора, значит объяснение «первый день торгов» не
работает — это обычные всплески оборота.

Сегодняшний топ-12 содержит шесть символов, которых в файле нет вовсе: **HEMI, PORTAL,
CYS, BTW, ACE, AIO**. Среди них `BTW` — тот самый символ, чьи 19 сигналов лежат в боевом
журнале вне вселенной (`docs/audit/pinned-coins-2026-08-17.md`, раздел 6): теперь видно,
откуда он взялся — кто-то применял правило к свежим данным.

**Вывод, который отсюда следует, и он не про данные, а про правило:** «оборот за 24 часа»
как критерий закрепления даёт состав, который назавтра неверен. Шесть символов из 27
(22%) стоят во вселенной по одному дню оборота. Чинится это либо мерой устойчивее
(медиана оборота за N суток), либо признанием, что вторая половина вселенной — не «топ по
обороту», а «то, что было в топе 2026-08-03». Оба варианта — решение владельца по §5:
первый меняет правило, второй меняет формулировку.

⚠ Чего замер НЕ говорит: он не сравнивает состав с тем, что было 2026-08-03, — тех
тикеров сохранено не было. Проверяется утверждение «это топ-12 по обороту», а не
добросовестность прошлого замера.

## 4. Мёртвые объявления: два, и одно из них моё

Механический обход (а не чтение): все ключи конфигураций и все константы верхнего
регистра в `src` сверены с числом употреблений в `src`, `gates`, `scripts`.

**`admission_required_bars = 200` в `config/universe.toml` — 0 употреблений.** Тот же
класс, что `bars_per_timeframe`, удалённый 2026-08-11. Хуже мёртвости: комментарий рядом
объявлял «порог — самое длинное требование среди величин §2.9», а 200 это требование
`ema200`. Самое длинное требование замерено и равно **304** (`adx14`,
`docs/audit/wilder-reference-2026-08-03.md`), и код берёт именно его
(`hunter admission --required 0` → `max(admission.REQUIRED_BARS)`). Ключ удалён, решение
владельца о варианте B сохранено комментарием — оно от ключа не зависело.

**`MESSAGES_PER_ANSWER` в `src/hunter/tgbot.py` — 0 употреблений, и внёс её я сам
2026-08-17**, в том же коммите, где писал, что она «используется в арифметике лимитов».
Не использовалась. Исправлено: теперь `publish_pinned` считает ею объём публикации и
предупреждает, если он длиннее минуты по лимиту Telegram.

После правок мёртвых констант в `src` — **ноль из 122 проверенных**.

## 5. Команды воспроизведения

Мёртвые ключи и константы:

```bash
uv run python -c "
import ast, pathlib, re, tomllib
files=[p for r in map(pathlib.Path,['src','gates','scripts']) for p in r.rglob('*.py')]
alltext=''.join(p.read_text(encoding='utf-8') for p in files)
for f in ['config/universe.toml','config/bot.toml']:
    sect=next(iter(tomllib.loads(pathlib.Path(f).read_text(encoding='utf-8')).values()))
    for k in sect:
        n=len(re.findall(re.escape(k), alltext))
        print(f'{f} {k:26} употреблений {n}', '⚠ МЁРТВЫЙ КЛЮЧ' if n==0 else '')
dead=[]
for p in [f for f in files if f.parts[0]=='src']:
    for node in ast.parse(p.read_text(encoding='utf-8')).body:
        if not isinstance(node,(ast.Assign,ast.AnnAssign)): continue
        for t in (node.targets if isinstance(node,ast.Assign) else [node.target]):
            if isinstance(t,ast.Name) and re.fullmatch(r'[A-Z][A-Z0-9_]{2,}',t.id):
                if len(re.findall(r'\b'+re.escape(t.id)+r'\b',alltext))<=1:
                    dead.append(f'{p.as_posix()}:{node.lineno} {t.id}')
print('мёртвых констант:', len(dead), dead)"
```

Сверка вселенной с её правилом — зонд сохранён в этом протоколе целиком (§7.4):

```bash
uv run python -c "
import asyncio, datetime as dt, ccxt.async_support as ccxt
from hunter.config import load_universe
CORPUS={'BTC','ETH','BCH','POL','ASTR','AEVO','ONDO','ANKR','ARPA','UNI','SAND','CFX','STX','CHZ','THETA','SUPER','NEO'}
NAMED={'XAU','XAG','PAXG'}
def crypto(m):
    i=m.get('info') or {}
    return i.get('underlyingType')=='COIN' and i.get('contractType')=='PERPETUAL'
async def main():
    uni=load_universe(); ex=ccxt.binanceusdm({'enableRateLimit':True})
    try: mk=await ex.load_markets(); tk=await ex.fetch_tickers(); srv=await ex.fetch_time()
    finally: await ex.close()
    cand={s:float((tk.get(s) or {}).get('quoteVolume')) for s,m in mk.items()
          if m.get('active') and m.get('settle')=='USDT' and m.get('quote')=='USDT'
          and crypto(m) and str(m.get('base')) not in NAMED
          and (tk.get(s) or {}).get('quoteVolume') is not None}
    order=sorted(cand.items(), key=lambda kv:-kv[1]); rank={s:i+1 for i,(s,_) in enumerate(order)}
    print('замер', dt.datetime.fromtimestamp(srv/1000, dt.UTC).isoformat(), '| кандидатов', len(cand))
    print('ТОП-12:', ', '.join(s.split('/')[0] for s,_ in order[:12]))
    alts=[s for s in uni.symbols if s.split('/')[0] not in CORPUS]
    keep=[s for s in alts if rank[s]<=12]
    for s in alts: print(f'  {s.split(chr(47))[0]:10} место {rank[s]:>4}  оборот {cand[s]:>16,.0f}')
    print(f'осталось в топ-12: {len(keep)} из {len(alts)}')
    print('живы и крипто:', sum(1 for s in uni.symbols if mk[s].get('active') and crypto(mk[s])), 'из', len(uni.symbols))
asyncio.run(main())"
```

## 6. Что осталось непроверенным

* **Утверждение «проходят 16 из 27» (допуск §2.9).** Не проверялось: `hunter admission`
  опрашивает 27 символов на шести ТФ, а прямо сейчас идёт полный проход службы, и второй
  потребитель лимита веса исказил бы обоих. Проверяется одной командой после прохода:
  `uv run python -m hunter admission`;
* **сам замер 2026-08-03.** Тикеров того дня не сохранено, воспроизвести его нельзя.
  Проверено только то, описывает ли правило состав СЕГОДНЯ;
* **числа, объявленные незамеренными** (`RESTART_PAUSE_S`, `CLOCK_RESYNC_S`,
  `MARKETS_RELOAD_S`, `map_ttl_minutes` и прочие): они и не претендуют на замер, каждое
  сопровождается пометкой «⚠ ЧИСЛО НЕ ЗАМЕРЕНО» и выводом, из которого взято. Эта сверка
  проверяла не их обоснованность, а наличие потребителя — потребитель есть у всех.
