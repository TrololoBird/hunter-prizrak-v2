# Детерминированный повтор: §10.6 условие 2 выполнено

Дата: 2026-08-04. До этого условие не выполнялось: кадры писались, но **не читались
никем**, и команды повтора не существовало.

## Зачем это владельцу

§10.3 дословно: «Любое изменение агент обязан предъявить как дифф повтора — на этих
сохранённых данных карточка была такой, стала такой. Вы видите два текста и разницу между
ними. Сегодня у вас такой возможности нет вовсе».

Теперь есть:

```bash
uv run python -m hunter replay --run-id last --diff
```

## Чего не хватало и что построено

**Пробел 1 — по живым сделкам нельзя было построить уровень.** `TradeHistogram` агрегатная,
времени не хранит, а профиль по стр. 26 натягивается ровно на бары структуры. То есть §2.2
работал только из суточного архива. Добавлен `BarBinnedTrades`: сделки раскладываются по
корзинам размером в младший ТФ вселенной, окно структуры складывается из целых корзин.

**Пробел 2 — не было единицы повтора.** Добавлен card.py: чистая функция от кадров,
печатающая ВЕСЬ расчёт §2 по-русски — тренд и структуры, уровни с зонами и стопами, цели и
РР, состояние уровня, переприоры, доп-факторы. Причины, по которым уровень не построен,
печатаются отдельным разделом (§4.3), а не пропускаются.

**Пробел 3 — не было сравнения.** Добавлен replay.py и подкоманда `replay`.

## Найденный дефект: карточка была НЕдетерминированной

Первый же повтор без единого изменения в расчёте дал **«ИЗМЕНИЛОСЬ» у 2 символов из 2**.

Причина: порядок таймфреймов. Живой прогон шёл по порядку вселенной
(5m, 15m, 1h, 4h, 1d, 1w), а повтор — по именам файлов
(15m, 1d, 1h, 1w, 4h, 5m). Расчёт тот же, текст разный.

Исправлено: порядок задаёт сама карточка — по длительности ТФ, от младшего к старшему, —
и не наследуется от вызывающего. Инструмент нашёл дефект на первом же применении.

## Контроль: прибор отвечает в обе стороны

Проверено, что `replay` способен сказать не только «совпало» (иначе он бесполезен):

| действие | что напечатал |
|---|---|
| ничего не менять | `совпало` — 2 из 2, 96 → 96 и 94 → 94 строк |
| порог `MIN_BOUNDARY_POINTS` 4 → 6 | `ИЗМЕНИЛОСЬ` — 96 → **75** и 94 → **72** строк, дифф показал какие |
| вернуть порог | `совпало` снова |

## Прогон

```bash
uv run python -m hunter run --symbols 2 --seconds 150 --seed-limit 400 --run-id demo
uv run python -m hunter replay --run-id demo
```

Живой прогон: 2 символа × 6 ТФ, 4700 баров, 1587 сделок, расхождение «бины против сырья»
2.370e-15, нарушений приёмки 0, файлов parquet 16, карточек 2.

## Что осталось непроверенным

- **Прогон в 150 с собирает сделки за 150 с**, поэтому почти все уровни в карточке помечены
  «окно структуры выходит за собранное». Это честно видно в разделе «УРОВЕНЬ НЕ ПОСТРОЕН»,
  но означает, что ветка построения уровня НА ЖИВЫХ сделках прогоном не покрыта — она
  проверялась только на суточном архиве. Нужен либо длинный прогон, либо подмешивание
  архива к живым сделкам.
- Повтор сверяет карточку с карточкой. Что сама карточка полна — не доказано: чего в ней
  нет, повтором не проверяется. Сейчас в ней нет стопового объёма §2.3 и размещения
  относительно старшей структуры.
- Проверено на 2 символах. По вселенной из 27 не гонялось.
