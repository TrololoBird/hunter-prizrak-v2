# Два числа, которых владелец видеть не должен был: `nan` и постоянное «ПЛОХО»

**Дата:** 2026-08-06. Оба найдены при разборе собственной работы, оба — в тексте, который
читает владелец, и оба класса §0/§4.3: величина без референта и красное при исправной
системе.

---

## 1. `nan` в карточке — и systematic перекос всех перцентилей

### 1.1. Как проявилось

```bash
uv run python -m hunter run --symbols 1 --seconds 5 --seed-limit 150 --horizon-days 0 --run-id short
```

Карточка на коротком ряду печатала:

```
   5м  полосы 0.18% (уже 1% истории) · EMA200 в nan% от цены
```

`nan%` — это значение без референта прямо в тексте владельцу.

### 1.2. Механизм

`polars_talib` отдаёт неопределённые значения как **NaN, а не как null**. Замер:

```bash
uv run python -c "
import math, polars as pl
from hunter import indicators
df = pl.DataFrame({'open':[1.0]*150,'high':[1.0]*150,'low':[1.0]*150,'close':[float(i) for i in range(150)]})
v = list(df.select(indicators.ema(200).alias('v'))['v'])
print('None:', sum(1 for x in v if x is None), ' NaN:', sum(1 for x in v if isinstance(x,float) and math.isnan(x)))
"
```

Результат: **None 0, NaN 150.** Все три функции factors.py проверяли только `is None`,
поэтому NaN проезжал насквозь — по-разному в каждой:

| функция | что делал NaN |
|---|---|
| `ma_touch` | `abs(nan − entry)/entry*100` → фактор с `distance_pct = nan`, и он печатался |
| `squeeze` | попадал в список ширин; дальше `w <= last` с NaN всегда ложно |
| `divergences` | сравнения с NaN всегда ложны → «дивергенции нет» вместо «индикатора нет» |

Ни один случай ничего не ронял и никуда не логировался.

### 1.3. Что оказалось хуже `nan`

`nan` был виден. Незаметным был `squeeze`: NaN-ширины **не попадали в числитель**
(сравнение ложно), но **попадали в знаменатель** (`len(widths)`). Значит перцентиль
занижался ровно на долю неопределённых баров — у полос с периодом 20 это первые 19 баров
ряда.

Перцентиль здесь не украшение: §4.1 называет «перцентиль собственной истории символа»
одной из трёх допустимых форм относительного порога. То есть перекошена была именно та
величина, которой §4.1 разрешает мерить.

Замер по диффу повтора: изменились **все 14 строк доп-факторов из 14**, и только
перцентиль — ширина и EMA200 те же.

| ТФ | было | стало |
|---|---:|---:|
| 1Н (хвост 341 из 345) | 82% | **87%** |
| 1ч | 87% | **91%** |
| 1Н | 13% | **14%** |
| 1ч | 45% | **47%** |
| 1ч | 66% | **68%** |
| 5м | 51% (без изменения ширины 0.52%) | **51%** |

Сдвиг всегда ВВЕРХ и тем больше, чем короче ряд: 19 неопределённых баров из 345 — это
5.5% знаменателя, из 500 — 3.8%.

### 1.4. Правка

`factors._absent(x)` — одно определение «величины нет» на весь модуль: `None` ЛИБО `NaN`.
Все три функции спрашивают его. Отдельно поправлена карточка: причина отсутствия фактора
берётся у `admission.check` и печатается числами.

```bash
uv run python -m hunter run --symbols 1 --seconds 5 --seed-limit 150 --horizon-days 0 --run-id short
```

Стало:

```
   5м  полосы 0.30% (уже 34% истории) · EMA200: BTC/USDT:USDT 5m: ema200 требует 200 баров, есть 149
```

## 2. `hunter check` печатал «ПЛОХО» всегда

### 2.1. Как проявилось

```bash
uv run python -m hunter check --symbols 1 --seconds 20
```

```
   ПЛОХО   Кадры сохранены для повтора
            записано 0 файлов в data\frames
ИТОГ: ТРЕБУЕТ ВНИМАНИЯ. Плохо в 1 из 9 проверок.
```

При полностью исправной системе: восемь проверок хорошо, одна плохо, всегда.

### 2.2. Механизм

Строка вердикта требовала `r.frames_written > 0`. Но `check` кадров НЕ ПИШЕТ — она только
собирает, и это записано в её же коде: «Здесь нужен ТОЛЬКО сбор: `check` отвечает на
вопрос «живы ли данные», карточки и леджер к нему отношения не имеют». Условие стало
невыполнимым по построению в тот момент, когда конвейер разделили на четыре шага
(коммит `00927cd`), и с тех пор проверка сообщала о поломке при её отсутствии.

⚠ Это опаснее пропуска. Красное при исправной системе учит владельца не верить красному —
а вердикт §7.5 существует ровно затем, чтобы ему верили.

### 2.3. Правка

Вопрос заменён на тот, на который ответ существует: **есть ли на диске то, что можно
повторить.** Отвечает состояние каталога кадров (`store.saved_runs`), а не текущий сбор,
и в самой строке сказано, что кадры пишет `hunter run`.

Стало: `ИТОГ: всё в порядке. Проверок пройдено: 9.`

## 3. Пересчёт протоколов

Перекос точный, односторонний и выражается формулой — числитель от NaN не меняется,
меняется только знаменатель:

    p_исправленный = p_напечатанный × N / (N − 19),   19 = период полос (20) минус 1

Формула ПРОВЕРЕНА, а не выведена на бумаге: на 10 парах (BTC/ETH × 5 ТФ, ряды по 999
баров) предсказание совпало с фактическим пересчётом **до сотых во всех десяти**, и все
десять значений сдвинулись вверх.

| пара | N | NaN | было | стало | по формуле |
|---|---:|---:|---:|---:|---:|
| BTC 1ч | 999 | 19 | 37.54% | 38.27% | 38.27% |
| ETH 1ч | 999 | 19 | 83.58% | 85.20% | 85.20% |
| BTC 4ч | 999 | 19 | 25.43% | 25.92% | 25.92% |
| ETH 1Д | 999 | 19 | 1.20% | 1.22% | 1.22% |

Множитель нечувствителен к длине ряда: при N от 300 до 1000 он лежит между 1.020 и 1.068.

### Что исправлено в протоколах

| протокол | было | стало |
|---|---|---|
| [`falsifiability-2026-08-04.md`](falsifiability-2026-08-04.md) | перцентили 1% … 83% | **1% … 85%** |
| [`course-complete-2026-08-04.md`](course-complete-2026-08-04.md) 1ч | 17% | **18%** |
| [`course-complete-2026-08-04.md`](course-complete-2026-08-04.md) 4ч | 33% | **34%** |
| там же, 5м и 15м | 6% и 1% | не изменились после округления |

Больше нигде в `docs/audit` перцентиль полос числом не приводится — проверено поиском по
«перцентил», «истории», `percentile`, `squeeze`.

⚠ Ни в одном случае поправка не переворачивает вывод протокола. В `falsifiability`
проверялось, способен ли прибор давать разные ответы, — разброс от единиц до восьмидесяти
процентов остаётся разбросом. В `course-complete` перцентиль был иллюстрацией, а выводы
документа строились на РР и состояниях уровней, которых поправка не касается.

⚠ Точный пересчёт `course-complete` НЕВОЗМОЖЕН: ни кадры того прогона, ни зонд не
сохранились. N взято по умолчанию команды (`--seed-limit 500`); фактическое могло быть
меньше из-за `continuous_tail`, поэтому 17% исправляется в 17-18%, а 33% в 34-35%.

### Задето, но не перцентилем

Строка «§2.9 EMA200 посчитана 40 из 40» в `falsifiability` тоже под вопросом, и
проверить её нельзя. `ma_touch` при неопределённой EMA возвращал фактор со значением
`nan`, а не отказ, — значит «посчитана» могло означать «посчитана в nan» для пар, где ряд
короче 200 баров. На сегодняшних данных все ряды по 999 баров, и таких пар нет.

## 4. Что осталось незамеренным

⚠ Оговорки по §7.6.
2. **NaN искали только в factors.py.** Любой другой потребитель `polars_talib`,
   проверяющий `is None`, имеет ту же дыру. Проверка была точечной, гейта нет.
3. **Правка `check` проверена в ОБЕ стороны**, и это единственный пункт, который здесь
   закрыт: при подменённом на пустой каталоге кадров `saved_runs()` даёт 0 прогонов и
   вердикт «ПЛОХО», на настоящем — 25 прогонов и «ХОРОШО». То есть строка способна
   краснеть, а не зелёная по построению — ровно та проверка, которой не хватало прежней
   редакции.
