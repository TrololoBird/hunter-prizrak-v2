## 2. Что говорит официальная справка TV про "видимую область" (V1)

* Диапазон VRVP — буквально бары, попавшие в окно графика; при скролле/зуме профиль
  пересчитывается. Никакого собственного "N по умолчанию" у индикатора нет — вход задаёт
  пользователь движением экрана.
* Значит у самого TV "видимая область" — НЕ число, а жест. Документированного "типично
  видно X баров" не существует (V1, V2): загруженная история 5–40 тыс. баров по тарифу —
  другая величина, а видимое окно зависит от монитора и зума.
* Официальная замена экрана у самого TV существует — Auto Anchored VP (V3): вместо экрана
  берётся якорь (сессия/месяц/квартал… или Highest High/Lowest Low окна Length). То есть
  TV сам, когда убирает экран из уравнения, переходит к якорям календаря и структуры.

Вывод: у автора нет одного "экранного N". На часовике он держит ~полтысячи баров
(сопоставимо с default 500 у V4 и "5 дней" V6 растянутыми на крипто-сутки), на дневке
отъезжает практически на всю историю инструмента. Общее у обоих экранов не число, а
покрытие: **на экране целиком помещается вся структура, о которой идёт речь, плюс
широкий контекст вокруг неё**.

Важно и второе: сам курс на стр. 63 ПОНИЖАЕТ статус VRVP — "индикатор используется только
для удобства поиска сильных объемов на графике. Для определения ТВХ и уровней — используем
индикатор "фиксированный профиль объема", т.к. он более точный". То есть измерительный
прибор курса — FRVP по фиксированному диапазону; VRVP — поисковый экран. Стр. 22 уточняет
роль: "Сила уровня определяется ТФ и объемом (смотрим по VRVP…)" — VRVP нужен, чтобы
СРАВНИТЬ наторговку структуры с окружением (пример там же: часовая наторговка может быть
объёмнее 4ч–1Д накопления).

## 4. Кандидаты на замену "видимой области" и кто их использует

| кандидат | кто использует | заметки |
|---|---|---|
| (а) фиксированные N последних баров ТФ | V4 (default 500), V5 (10–1000), V6 (5 дней), V7 (24 ч); TV-якоря Highest High/Lowest Low тоже берут "последние Length баров" (V3) | консенсусного N нет — везде свободный параметр; медиана дефолтов ~500 баров / ~неделя. Детерминирован и прост; референт слабый ("так настроено по умолчанию") |
| (б) окно от значимого свинга/структуры | ОФИЦИАЛЬНЫЙ TV Auto Anchored VP (V3: Highest High, Lowest Low, Highest Volume, Earnings); pivot/swing-профили сообщества (V12); брекеты/balance areas Далтона (V11) | единственный кандидат, где у окна есть рыночный референт; ровно это делает и курсовой FRVP-сценарий (профиль по границам накопления) |
| (в) сессионный/суточный профиль классики | Steidlmayer/CBOT (V10), py-market-profile (V8), Letian Wang (V9); TV Auto=Session на intraday (V3) | канон для бирж с сессиями; у крипто 24/7 "сессия" — соглашение (UTC-сутки, V7). Годится как единица нарезки, не как "экран" |
| (г) composite за K дней | классика: composite = слияние сессий за неделю/месяц/год ЛИБО по границам брекета (V10, V11); TV Auto=Month на 1D, Quarter/Year/Decade выше (V3) | канонического K НЕТ: фиксированные K — календарные (5/21/…), содержательные composite у Далтона режутся ПО СТРУКТУРЕ (брекет), т.е. сводятся к (б) |

Распределение по источникам: (б) поддержан официальным TV (V3), классикой (V11) и
сообществом (V12); (а) — только дефолты реализаций, без канона; (в) — канон классики, но
для сессионных рынков; (г) без структурных границ вырождается в календарное (а).

## 5. Рекомендация (⚠ это РЕКОМЕНДАЦИЯ, не решение — решение за владельцем)

**Основная замена "видимой области" — кандидат (б): окно от структуры.** Для роли,
которую VRVP играет в курсе (сила уровня = сравнить наторговку структуры с окружением,
стр. 22), окном взять диапазон [начало структуры-родителя уровня − контекст; момент
оценки], где контекст расширяет окно так, чтобы структура занимала малую долю окна —
у автора на обоих скриншотах сама структура занимает явно меньшую часть экрана.
Обоснование: (1) это единственный кандидат с рыночным референтом у числа; (2) сам TV,
убирая экран, переходит к якорям (V3); (3) composite Далтона режется по брекету (V11);
(4) фактические экраны автора (~570 баров на 1ч, ~1200 на 1Д) — это как раз "вся
структура + широкий контекст", а не константа.

**Калибровочная константа, если владелец предпочтёт (а):** N = 500 последних баров ТФ
карточки — медиана дефолтов открытых реализаций (V4–V6) и порядок фактического экрана
автора на 1ч; но тогда честно записать, что на 1Д автор держит на экране ~1200 баров
(фактически всю историю), т.е. одно N на все ТФ с курсом расходится.

**Чего НЕ делать:** выводить N из "сколько баров TV показывает по умолчанию" — такого
числа не существует (V1, V2): видимая область у TV задаётся рукой пользователя, а
тарифные 5000–40000 — лимит загрузки истории, не экран.

Отдельно зафиксировать: по стр. 63 VRVP в курсе — ПОИСКОВЫЙ инструмент ("для удобства
поиска"), измерительный — FRVP по фиксированному диапазону. Значит эквивалент VRVP нужен
системе только для контекстного сравнения "наторговка структуры против окружения", а не
для построения самих уровней — уровни уже покрыты FRVP-портом по спеке 2026-08-09.

## Чего выяснить не удалось

1. Точные даты на шкале стр. 63: цифры дней читаются на пределе разрешения исходного
   скриншота (оценка "~24 дня" — по числу и шагу подписей, не по точному чтению каждой).
2. Default Length у якорей Highest High/Lowest Low в TV Auto Anchored VP — справка (V3)
   значения не называет.
3. "Типичное число видимых баров по умолчанию" у TV — не документировано нигде;
   по-видимому, такой константы нет (зависит от окна браузера и зума).
