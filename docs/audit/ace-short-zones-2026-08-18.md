# Почему по ACE не было шорт-зон: три дефекта данных, найденные одним вопросом

Дата: 2026-08-18. Повод: вопрос владельца «почему по ace не найдены шорт зоны?!» и
приказ «перепроверь вручную самостоятельно».

## Хронология и опровержение собственного ответа

Мой первый ответ — «цена выше всех структур, сверху пусто» — **ОПРОВЕРГНУТ ручной
проверкой по сырым свечам**: 2026-08-14 ACE делал хай 0.37888 (текущая цена на момент
разбора 0.2247), 2026-08-15 — 0.34439. Свежая история выше цены была, и детектор
свингов её видел (свинг-хай 4ч = 0.37888).

Дальше разбор показал: часть отсутствия шорт-зон законна по методу, а часть — цепочка
из трёх дефектов ДАННЫХ, из-за которых карта не строила уровни старших ТФ.

## Законная часть (по курсу)

* у цен 0.23–0.38 нет структуры-накопления: памп и обвал уложились в двое суток;
  шпиля без структуры уровнем не является (корпус seg6: «без слома уровень слабый —
  просто шпиля»);
* шорт-ПП после пампа не подтверждён: лои после обвала (0.1302/0.13102) целы;
* все ранее подтверждённые шорт-уровни (максимум 0.1975) — worked_off/flipped, а в
  зоны бота идут только активные.

## Дефект 1: докачка профиля только минутками

`backfill_profile_bars` качал окна структур ТОЛЬКО для `uni.profile_timeframe` (1m),
полагая, что окна старших ступеней лестницы intrabar-ТФ «читают ряды, уже собранные
засевом». Но засев собирает `seed_depth` (~180 суток на ТФ), а окна дневных и
недельных структур уходят глубже. Итог: недельная структура дек-2025..мар-2026 (цены
0.137–0.3298, хай ВЫШЕ текущей цены) отказывала «окно покрыто свечами 1h не полностью —
417 из 2352». Отказ честный по §4.3, но ложился систематически на старшие ТФ — ровно
перекос по измерению из правила сводки отказов. У монет вселенной он частично
маскируется накопленным хранилищем; у монет по запросу — нет.

**Правка:** докачка по всем ступеням лестницы `PROFILE_LADDER` (окна группируются по
`intrabar_timeframe`), `trade_source` подмешивает хранилище по всем ступеням.

## Дефект 2: пагинация свечей выбрасывала ГОЛОВУ окна

`_fetch_ohlcv_paged` резал результат безусловным `ordered[-limit:]` («последние
limit»), а последняя страница выходит за правый край окна на неполную страницу — до
`OHLCV_PAGE - 1` лишних баров. При явном `since` это сдвигало ВСЁ окно вправо:
запрос «2690 баров 15м с 6 февраля» возвращал ровно 2690 баров, но с 9 февраля
(сдвиг 304 бара = размер перехлёста). Контроль: сырой ccxt с тем же `since` отдаёт
бары ровно с запрошенной метки — недостача была наша, не биржи. Путь без пагинации
(≤1000 баров) якорится к голове самой биржей, то есть два пути одного метода
противоречили друг другу.

**Правка:** якорь обрезки по `since`: явный `since` — голова (`ordered[:limit]`),
без `since` — хвост (последние N от «сейчас»). Контроль в обе стороны: с `since`
первый бар == lo; без `since` последний бар свежий.

Побочная победа: этот же дефект оставлял дыру в НАЧАЛЕ хвоста засева при догоне
(`since` из `missing_tail_since` + глубина > предела страницы) — источник части
предупреждений «разрыв сетки».

## Дефект 3: критерий «участок уже в кэше» был слеп к дырам внутри окна

Критерием служил `missing_tail_since` — курсор ХВОСТА от последнего сохранённого
бара. Хранилище минуток ACE начиналось раньше окна и кончалось позже, а три окна
свежих 5м-структур лежали в его внутренней дыре: участок объявлялся кэшированным,
профиль отказывал «покрыто не полностью», и чинить было некому.

**Правка:** критерий тот же, что у читателя (`CandleWindows.window`): счёт полных
баров в самом окне; не хватает — участок перекачивается целиком, `append` сливает.

## Дефект 4 (следствие 1-3): двойная отсечка окон

Уровни при сборке по запросу строятся по рамке кадра (`frame_bars` = 180 баров
СВОЕГО ТФ; для 1Н это 3.5 года), а докачка резала окна горизонтом в СУТКАХ (180
суток = 25 недельных баров). Недельные структуры возрастом 26–180 недель получали
уровень «в плане», но не получали свечей — вечный отказ. **Правка:** при заданном
`frame_bars` горизонт не применяется — критерий закачки равен критерию потребителя.
Боевой прогон (`frame_bars is None`) по-прежнему режется горизонтом: его охват —
решение владельца о цене.

## Результат (живые прогоны, путь бота, символ ACE)

| прогон | уровней в карте | активных шортов | отказов покрытия старших ТФ |
|---|---|---|---|
| до правок | 16 | 0 | 5 (окна 15м/1ч под 1Д/1Н структуры) |
| после правок 1-2 | 18 | 1 (0.2747 ·1Н) | 4 (окна 2024-2025, резал горизонт) |
| после правки 4 | 22 | 3 (0.2747, 0.644, 5.35 ·1Н) | 0 |

Появившиеся шорт-зоны над ценой: 0.2295–0.3019 (ПОК 0.2747), 0.461–0.683 (0.644),
4.05–9.81 (5.35) — все от недельных структур, которые карта раньше не строила.
Свечей докачано: 2948 + 192 + 15626. Проверка правки якоря: тот же вызов с `since`
начал отдавать первый бар == запрошенной метке, без `since` — свежий хвост.

Отдельно: в ответ бота теперь идут и снятые уровни (`zones_of` в окне
`RETIRED_WINDOW_MS`, как в `read_map`), и пустая сторона называет причину
(«N отработано ценой, M перевёрнуто пробоем»), а не молчит «пока нет».

## Что осталось непроверенным

* полный прогон вселенной с новой докачкой (стоимость первого цикла вырастет —
  разово докачиваются старые окна старших ТФ всех символов вселенной; в боевом
  прогоне горизонт по-прежнему 180 суток, так что рост ограничен);
* дифф повтора §10.6 на пакет правок смены — расчётная геометрия не тронута, но
  карта меняется составом ДАННЫХ; повтор строится из сохранённых кадров и этого
  не увидит по построению — предъявлять надо живым прогоном (сделано на ACE);
* сводка отказов по ТФ в боевом цикле после правок (ждёт следующего цикла службы).

## Команда воспроизведения (§7.3)

Числа таблицы «Результат» получены ЖИВЫМ прогоном пути бота по одному символу — тем
же, каким отвечает `/зоны ace`. Повтор из сохранённых кадров эти числа НЕ
воспроизводит по построению: правки меняли состав ДАННЫХ, а не расчёт.

```bash
uv run python -c "
import asyncio
from hunter import run, universe, tgbot
from hunter.tgbot import BARS_ON_CHART, zones_of
from hunter import clock

async def main():
    uni = universe.load(universe.DEFAULT_PATH)
    one = uni.model_copy(update={'symbols': ('ACE/USDT:USDT',)})
    report, sources = await run.collect(one, 0, 0, 180, frame_bars=BARS_ON_CHART)
    decided = run.decide_once(report, one, sources, BARS_ON_CHART)
    got = decided['ACE/USDT:USDT']
    z = zones_of(got, clock.now_ms())
    print('уровней в карте', len(got.decisions))
    print('активных шортов', sum(1 for x in z if x.side == 'short' and not x.retired_at_ms))
    for x in z:
        if x.side == 'short':
            print(' ', x.lo, x.hi, x.poc, x.timeframe)
asyncio.run(main())
"
```

шортов 3 (ПОК 0.2747, 0.644, 5.35 — все 1Н), отказов покрытия старших ТФ 0; свечей
докачано за три прогона 2948 + 192 + 15626. Хранилище РАСТЁТ, и та же команда позже
даст другой состав карты: расхождение читается как доливка данных, а не опровержение.
Строки «до правок» и «после правок 1-2» воспроизводятся только откатом кода на
соответствующие правки — это исторические замеры, и они помечены как таковые.
