## Сверка с фактической реализацией

Каждое расхождение — пробел СПЕЦИФИКАЦИИ, а не ошибка субагента: там, где §2 допускает две
несовместимые реализации, он недоспецифицирован.

| пробел, найденный по одной спецификации | что выбрал субагент | что выбрал код | совпало? |
|---|---|---|---|
| **определение свинга** — в §2 отсутствует полностью | ZigZag 1.5·ATR либо фрактал k=2, выбор назван произвольным | фрактал Вильямса k=2, 5 баров, три источника по §0.2 | **нет** (код обоснован лучше, но §2 не содержит ни того ни другого) |
| **ширина бина профиля** («привязаны к `tickSize`») | ширина = `tickSize`·m, подобрано под ≤200 бинов | ширина = ровно `tickSize` | **нет** |
| **цена бина** | центр бина | нижняя граница бина | **нет** |
| **окно профиля** | от первого бара структуры до бара выхода, выход исключён | то же (`structure_window_ms`) | **да** |
| **«полноценный выход»** | 2 подряд тела за границей, тело ≥ 0.10·ATR | 2 подряд полных тела (`CONFIRM_BODIES=2`), порога размера тела нет | **частично** |
| **тай-брейк при равных бинах** | ближайший к VWAP окна | `NotReady` — ничья не разрешается | **нет** (код строже и лучше по §4.3) |
| **стоп 1–3% — от чего** | от цены границы | от цены границы | **да** |
| **сглаживание профиля** | не сглаживать | не сглаживать | **да** |
| **отсутствие `aggTrade` на истории** | уровень не создаётся, `NotReady` | то же | **да** |
| **«сила уровня = ТФ и объём»** | два поля отдельно, без свёртки | два поля отдельно (`timeframe`, `structure_volume`) | **да** |
| **вариант расширения Value Area** | парами | по одному (`Expansion.SINGLE`), оба реализованы, расхождение замерено | **нет** |

Из одиннадцати существенных мест независимая добросовестная реализация совпала с проектной
в **пяти**. В шести — разошлась, и в трёх из них (ширина бина, цена бина, определение
свинга) расхождение прямо двигает цену уровня, то есть цену входа.

**Это и есть измеренная величина риска §2 как критерия:** документ, объявленный
единственным источником требований, допускает реализации, которые дают разные уровни на
одних и тех же данных.

## Три места, где спецификация противоречит сама себе (существенные)

1. **§5 против §2.8.** §5 требует строить профиль на реальных сделках; §2.8 отдаёт
   главенство старшим ТФ. Публичный `aggTrade` не даёт глубины, нужной структуре 1Д/1Н.
   По букве §5 старшие ТФ уровней не дают — что и замерено (R-01: 1Н — 0 из 26).
2. **§2.2 против §3 и §4.2.** §2.2: «сила уровня определяется таймфреймом и объёмом».
   §3 запрещает составные метрики, §4.2 — весовые суммы. Как соединить ТФ и объём, не
   строя свёртки, документ не говорит. Код решает это, НЕ соединяя их вовсе, — решение
   верное, но выведено оно не из §2.2.
3. **§0 против §0.2.** §0: «нет референта — величина не пишется». §0.2 отправляет за
   недостающими числами к замеру. Замер требует уже работающего детектора, детектор
   требует чисел. Круг замкнут; как из него выйти, документ не описывает — на практике
   выход находится (число называется явно с пометкой «не замерено»), но это ПРАКТИКА, а не
   правило документа. Ровно об этом же находка Э-6 прошлого разбора.

## Команды воспроизведения (§7.3)

Числа этого документа — счёт недоспецифицированных мест, а не замер на данных;
воспроизводятся они прочтением. Проверяемое следствие — что спецификация НА МОМЕНТ ТЕСТА
ПОЛЬЗОВАЛАСЬ понятиями свинга и экстремума, но не ОПРЕДЕЛЯЛА их. Смотреть надо версию под
тегом `pre-audit-2026-08-06`: слово «фрактал» внесено в документ уже правкой фазы 8, и
проверка по рабочему дереву дала бы обратный ответ.

Фактический вывод команды на теге: `{'фрактал': False, 'zigzag': False, 'экстремум': True,
'свинг': True}`. То есть §2.5 говорит «цена не обновила экстремум», а §8 требует «детекция
свингов» — при том, что ни один способ их найти документом не назван. Это и есть форма
пробела: не умолчание о предмете, а **употребление термина без определения**.

```bash
uv run python -c "import subprocess; t=subprocess.run(['git','show','pre-audit-2026-08-06:docs/FOUNDATION.md'],capture_output=True).stdout.decode('utf-8').lower(); print({w: w in t for w in ['фрактал','zigzag','экстремум','свинг']})"
```

Git Bash и невиден Python — это уже ломало проверки, и в `.github/workflows/ci.yml` про
это стоит отдельное предупреждение.
