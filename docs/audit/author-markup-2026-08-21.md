## Мера совпадения

**С чем сверяем.** Не только с ПОКами: карточка рисует ТРИ линии на уровень — ПОК и оба
края зоны, — а у автора часть подписей заведомо края зон (79900.2, 80780.0). Сверять ПОК
с краем зоны значит считать промахом то, что промахом не является.

**Допуск взят из данных, а не назначен.** В промахах есть разрыв: настоящие попадания
лежат в 0.002–0.14%, ближайшие непопадания начинаются с 0.34%. Основной допуск —
**0.05%**.

**Верхняя граница осмысленности допуска замерена.** Равноотстоящая решётка из 330 цен в
том же размахе покрывает 17 линий автора из 17 уже при допуске 0.1%. Значит любая
цифра покрытия при допуске 0.1% и слабее не значит НИЧЕГО.

**Контроль — случайностное испытание**, 20000 раскладок того же размера в том же
диапазоне. `p` — доля раскладок, давших результат не хуже нашего.

## Как повторить

Скрипт меры в репозиторий не кладётся (правило про зонды). Первичные данные — список
линий выше; всё остальное берётся из леджера:

```bash
uv run python -m hunter serve --cycles 1 --symbols 1 --run-id btcmatch
```

Затем: взять из `data/ledger.sqlite3` строки `levels` по BTC (`price`, `zone_lo`,
`zone_hi`, `state`, `to_ms`), собрать из них тройки линий, для каждой линии автора найти
ближайшую нашу и посчитать промах в процентах от цены автора. Контроль обязателен и
делается тем же кодом по списку случайных цен в том же размахе.

⚠ Числа выше привязаны к состоянию леджера на момент замера: 117 строк карты BTC,
из них активных 7. При повторе сверяйте этот отпечаток — карта живёт между прогонами.
