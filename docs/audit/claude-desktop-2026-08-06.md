# Настройка Claude Desktop под этот проект — 2026-08-06

Задача владельца: изучить настройки настольного приложения (навыки, плагины, коннекторы,
расширения, режим разработчика, общие) и составить два списка — что подключить и что
отключить, — а затем сделать это.

Здесь: карта поверхностей приложения, ЗАМЕР текущего состояния аккаунта, оба списка с
причинами, что из этого уже лежит в дереве, что осталось владельцу кликами, и контроль
нового гейта в обе стороны.

⚠ Граница ответственности названа сразу. Настройки аккаунта (коннекторы, навыки и
плагины в разделе Customize) живут на стороне claude.ai, и сессия их только ЧИТАЕТ:
включить и выключить их может владелец, инструмента «отключить» у агента нет. Всё, что
можно закрепить в репозитории, закреплено файлами и проверяется гейтом.

## 1. Карта: три поверхности, три места настройки

Приложение — это три вкладки, и они настраиваются по-разному. Без этой карты оба списка
читаются как произвольные.

| поверхность | откуда берёт инструменты | что на неё влияет из репозитория |
|---|---|---|
| **Chat** | коннекторы и навыки аккаунта (Customize), плюс серверы из файла разработчика | ничего |
| **Cowork** | то же, что Chat: Customize синхронизируется через аккаунт, а не через каталог CLI | ничего |
| **Code** | `.claude/settings.json`, `.mcp.json`, `.claude/skills/`, `.claude/commands/`, `CLAUDE.md` — те же файлы, что читает CLI | всё |

Три следствия, каждое из которых меняет решение:

1. **Code читает файлы репозитория, Chat и Cowork — нет.** Значит защита проекта от
   постороннего инструмента ставится в `.claude/settings.json` и действует только в
   Code. Для Chat остаётся дисциплина владельца или отключение коннектора в аккаунте.
2. **Файл разработчика течёт в обе стороны.** Настольное приложение загружает MCP-серверы
   из `%APPDATA%\Claude\claude_desktop_config.json` (Windows) не только в чат, но и в
   локальные сессии вкладки Code — и при совпадении имён его определение ПЕРЕБИВАЕТ
   определение из репозитория. То есть сервер, добавленный там «для чата», окажется в
   расчётной сессии мимо всех настроек проекта.
3. **Навык стоит контекста постоянно.** Документация Anthropic называет цену метаданных
   навыка порядка 100 токенов, и они загружаются при старте независимо от того, нужен
   навык или нет. Двадцать лишних навыков — это не «просто лежат».

**Почему Context7 — единственный сервер в `.mcp.json`.** В `pyproject.toml` записано
дословно: «Пинить жёстко: polars быстро меняет API, и агент, помнящий старую версию,
изобретёт несуществующий метод». Это и есть задача Context7: документация по КОНКРЕТНОЙ
версии вместо памяти модели. Зависимости здесь пиньются точкой (`ccxt==4.5.70`,
`polars==1.43.2`, `pydantic==2.13.4`), то есть цена ошибки памяти максимальная.

Ключ `enabledMcpjsonServers` НЕ выставлен намеренно: приложение спросит подтверждение
при первом использовании сервера. Автоодобрение удалённого сервера, вписанное в
репозиторий, сработало бы и на чужой машине без её ведома.

### A2. Что владелец делает кликами — по одному разу

1. **СНАЧАЛА выключить обход разрешений, и только потом говорить о режиме прав.**
   Settings → Claude Code → «Allow bypass permissions mode». Замер владельца 2026-08-06
   (коммиты `ee112aa` и `5e0edb1` в `main`): правило `Bash(echo ПРОБА-ЗАПРЕТА *)` было
   добавлено в `permissions.deny`, и команда ВЫПОЛНИЛАСЬ; две другие формы записи дали то
   же. Причина найдена в настройках аккаунта — там включён обход разрешений
   (`bypassPermissionsOptInByAccount`, `bypassPermissionsGateByAccount`), а в этом режиме
   не проверяется НИ ОДНО правило: ни `allow`, ни `deny`.

   Это худшая форма дефекта из тех, что ловит этот проект: защита выглядит настроенной и
   не действует. Пока обход включён, любое обсуждение `defaultMode` бессмысленно — режим
   есть, а прав нет. Поэтому `deny` из настроек проекта владелец удалил целиком и перенёс
   запреты в хук `.claude/hooks/guard_destructive.py`, проверенный шестнадцатью пробами
   в обе стороны. Хуки работают и при включённом обходе — это доказано трижды за сутки.

   После выключения обхода имеет смысл поставить в блок `permissions` первой строкой:
   ```json
   "defaultMode": "acceptEdits",
   ```
   Правки применяются без вопроса, команды по-прежнему спрашиваются: коммит держит хук
   гейтов, каждая сессия работает в своей копии, а вопрос на каждую правку обучает
   нажимать «разрешить» не читая — то же вырождение, что «печать вместо кода возврата».
   ⚠ Эту строку агент поставить не смог: классификатор прав блокирует правку агентом
   собственных разрешений. Это верное поведение, и потому строка здесь, а не в коммите.

2. **Приватность: обучение на переписке — выключить.** Settings → Privacy → «Help
   improve Claude» (или прямо `claude.ai/settings/data-privacy-controls`). Для планов
   Free/Pro/Max он по умолчанию ВКЛЮЧЁН. Репозиторий сделан приватным по названной
   причине: в дереве лежит мини-курс PrizrakTrade целиком и расшифровки разборов автора
   — чужой материал. Обсуждение этого материала в переписке — тот же материал.

3. **Окружение сессии — Local.** Выпадающий список окружения слева от поля ввода.
   Живой прогон возможен только там: замер 2026-08-03 на арендованном раннере GitHub дал
   от Binance `HTTP 451 Service unavailable from a restricted location`. Про облачные
   сессии Anthropic это не замерено — но площадка того же класса, и проверяется одной
   командой:
   ```bash
   uv run python -m hunter check --symbols 1 --seconds 60
   ```
   Если оттуда приходит 451 — облачные сессии годны для правки кода и гейтов, но не для
   живых прогонов.

4. **Переменные окружения для локальных сессий.** Окружение → **Local** → шестерёнка.
   Приложение не наследует профиль оболочки целиком: с Dock/Finder на macOS оно читает
   оттуда только `PATH` и фиксированный набор переменных, на Windows профили PowerShell
   не читает вовсе. Всё, что нужно живому прогону сверх этого, задаётся здесь.

5. **Расписание для `/check`.** Scheduled tasks в приложении: раз в сутки запускать
   `/check`. Служба 24/7 собирает данные, а вердикт §7.5 сейчас появляется, только когда
   о нём вспомнят.

6. **Первое подключение Context7.** В сессии Code набрать `/mcp` и пройти вход. Сервер
   объявлен в `.mcp.json`, но авторизация — разовое действие на машине.

## 4. СПИСОК B — что отключить или перенастроить

### B1. Четыре коннектора рыночных данных — главный пункт списка

**Crypto.com, CoinDesk, Alpha Vantage, LunarCrush.** Причина не в том, что они плохие, а
в том, что их числа НЕЛЬЗЯ отличить от наших, глядя на ответ.

Транспорт проекта — Binance USDⓈ-M, бессрочные контракты (`src/hunter/exchange.py`,
вселенная вида `BTC/USDT:USDT`). Коннектор отдаёт другую площадку и, как правило, спот.
Свеча, профиль объёма и уровень, снятые оттуда, ПОХОЖИ на наши и не равны им. Дальше
работает механизм, описанный в CLAUDE.md: число докладывается, звучит правдоподобно и
проверить его нечем.

Второе, независимое основание: FOUNDATION §7.3 — «каждое числовое утверждение
сопровождается командой воспроизведения; число без команды не фиксируется». У ответа
коннектора команды воспроизведения нет ПО ПОСТРОЕНИЮ: это разовый вызов чужого сервиса,
а не расчёт из собранных кадров. Такое число нарушает §7.3 самим фактом появления.

Сделано: `disableClaudeAiConnectors` в `.claude/settings.json` — в сессиях Code этого
репозитория коннекторы аккаунта не подгружаются вовсе.

Осталось владельцу: Customize → Connectors → отключить эти четыре, если они не нужны в
чате для другой работы. В Chat и Cowork настройка репозитория не действует.

### B3. Что НЕ ставить

* **Расширения (`.mcpb`) для файлов, git и терминала.** Вкладка Code умеет это
  собственными инструментами, а расширение — это ещё один локальный процесс с доступом к
  диску. Больше поверхности, тот же результат.
* **Ничего в файле разработчика.** `%APPDATA%\Claude\claude_desktop_config.json` держать
  пустым (`{"mcpServers": {}}`). Причина в §1: его серверы попадают и в сессии Code, и
  при совпадении имени перебивают `.mcp.json`. Это единственный способ обойти защиту
  из §4 незаметно.
* **Computer use** (Settings → General): по умолчанию выключено, включать незачем —
  задач без CLI здесь нет. Побочно: приложение и так ограничивает торговые платформы
  режимом «только смотреть».
* **Bypass permissions** (Settings → Claude Code): режим без единого вопроса. В дереве
  живёт леджер, который накапливается только временем и не восстанавливается. ⚠ Замером
  2026-08-06 установлено, что у аккаунта он ВКЛЮЧЁН и потому правила прав не работают
  вовсе — см. §3, пункт A2.1: это не совет на будущее, а действующее состояние.

### B4. Что перенастроить, а не отключить

* **Auto-archive after PR merge or close** (Settings → Claude Code) — включить. Рабочие
  копии сессий лежат в `.claude/worktrees/`; при симлинке `data` брошенная копия — это
  ещё одна ссылка на боевые данные.
* **Worktree location** — оставить по умолчанию. Перенос за пределы проекта сломает
  относительные пути в `.claude/settings.json`.
* **Browser pane и auto-verify** — не трогать: в проекте нет веб-приложения, файл
  конфигурации предпросмотра не нужен, автопроверка правок браузером ни разу не запустится.

## 6. Контроль гейта: способен ли он выдать иной ответ

CLAUDE.md запрещает докладывать «нарушений 0», не показав, что прибор умеет отвечать
иначе. Зонд подсаживал по одному нарушению каждого класса в КОПИЮ конфигурации и
запускал гейт с рабочим каталогом в копии.

| подсаженное нарушение | код возврата | что напечатал |
|---|---|---|
| контроль: копия как в дереве | 0 | нарушений 0 |
| опечатка в имени ключа (`disableClaudeAiConnnectors`) | 1 | ключ не признаётся приложением |
| объявленный хук без файла (удалён `.claude/hooks/commit_gate.py`) | 1 | объявлен хук, файла нет |
| файл хука есть, объявления нет (`.claude/hooks/guard_destructive.py`) | 1 | не запускается никогда |
| навык без `description` | 1 | по нему навык и находят |
| сервер MCP с `url`, но без `type` | 1 | читается как stdio и пропускается |
| несуществующий режим прав (`acceptEdit`) | 1 | такого режима нет |
| контроль в обратную сторону: копия восстановлена | 0 | нарушений 0 |

Восемь запусков, шесть классов нарушений пойманы, обе стороны контроля сошлись. Зонд
удалён по §7.4; его тело — ниже, чтобы замер оставался воспроизводимым:

```bash
# копия конфигурации, подсадка нарушения, запуск гейта с cwd в копии
WORK=/tmp/probe-claude-config
rm -rf "$WORK" && mkdir -p "$WORK"
cp -r .claude config "$WORK"/ && cp .mcp.json "$WORK"/
python - "$WORK" <<'PY'
import json, sys
p = sys.argv[1] + "/.claude/settings.json"
d = json.load(open(p, encoding="utf-8"))
d["disableClaudeAiConnnectors"] = True      # опечатка: лишняя n
json.dump(d, open(p, "w", encoding="utf-8"), ensure_ascii=False, indent=2)
PY
(cd "$WORK" && uv run --group gates python "$OLDPWD/gates/claude_config.py"); echo "код возврата: $?"
```

⚠ Контроль показывает, что гейт не заперт в одном ответе. Он НЕ показывает, что
конфигурация верна: гейт проверяет ОБЪЯВЛЕНИЕ (ключ признаётся, файл на месте, шапка
разбирается), а не то, что приложение повело себя так, как задумано. Проверка поведения
— запуск сессии, и она за пределами CI.

## 7. Поиск по экосистеме: что из существующего берём и что отвергаем

Отдельный проход веб-поиском и по реестрам: какие ГОТОВЫЕ коннекторы, навыки и плагины
помогут Claude Code именно на этом дереве. Критерий отбора один и он проектный: инструмент
либо помогает ПИСАТЬ и ПРОВЕРЯТЬ код, либо не берётся. Инструмент, приносящий рыночные
числа, отвергается независимо от качества — §4.

### 7.1. Берём

**Плагин `astral` из маркетплейса `astral-sh`** — навыки `uv`, `ruff` и `ty` от авторов
самих инструментов. Совпадение с этим деревом точное: здесь всё гоняется через `uv run`,
линтер — `ruff` с собственным списком запрещённых вызовов, а `uv.lock` в корне. Проверено
по исходнику, а не по обзору: [манифест плагина](https://github.com/astral-sh/claude-code-plugins/blob/main/plugins/astral/.claude-plugin/plugin.json),
навыки `uv`, `ruff` и `ty` в каталоге `plugins/astral/skills/`, лицензия MIT.

Прописано в `.claude/settings.json` (`extraKnownMarketplaces` + `enabledPlugins`), то есть
поднимется и в облачной сессии, а не только на машине владельца.

⚠ Вместе с навыками плагин объявляет **LSP-сервер `ty`** — это отдельный проверяльщик
типов Astral, не mypy. Гейтом остаётся `mypy --strict`; расхождение между ними — повод
верить гейту, а не подсказке. Если шум мешает, плагин снимается той же строкой.

**Сервер `github-actions` в `.mcp.json`** — официальный удалённый MCP GitHub, **набор
только для Actions и только на чтение**:
`https://api.githubcopilot.com/mcp/x/actions/readonly`. Адрес взят из документации
самого сервера — [docs/remote-server.md](https://github.com/github/github-mcp-server/blob/main/docs/remote-server.md),
где перечислены 18 наборов и у каждого своя ссылка с суффиксом `/readonly`.

Зачем именно этот, а не полный: §7.4 объявляет CI постоянной проверкой, и вопрос
«почему CI красный» задаётся чаще всех остальных. Полный набор тянет ещё полтора десятка
инструментов в контекст и умеет писать в репозиторий; для чтения прогонов и логов заданий
хватает одного набора, который писать не умеет по построению.

### 7.2. Отвергаем — с причиной, а не по вкусу

| кандидат | почему нет |
|---|---|
| MCP бирж и рыночных данных (ccxt, CoinGecko, CoinDesk и прочие) | §4: другая площадка, спот вместо бессрочных, и у числа нет команды воспроизведения |
| MCP для pandas | `pandas` запрещён в `pyproject.toml` везде, кроме гейтов-оракулов: он там ВТОРАЯ независимая реализация, а не рабочий инструмент. Навык, зовущий pandas, ломает смысл оракула |
| навыки «polars data engineering» со сторонних витрин | учат СВЕЖЕМУ API, а здесь `polars==1.43.2` прибит гвоздями. Задачу «документация по нужной версии» уже решает Context7, и решает точнее |
| MCP для SQLite (леджер) | замер: `mcp-server-sqlite` на PyPI — версия `2025.4.25`, это тот самый эталонный сервер, **сданный в архив** с неисправленной инъекцией SQL; `sqlite-explorer-fastmcp` на PyPI не опубликован вовсе. Пускать неподдерживаемый чужой код к боевому леджеру нельзя: §10.2 держит ЕДИНСТВЕННОГО писателя, и гейт `production_writer.py` это стережёт |
| MCP файловой системы, git, fetch | вкладка Code умеет это сама; лишний процесс с доступом к диску без нового умения |
| Serena и прочие «семантические навигаторы» по коду | окупаются на больших деревьях; здесь 30 модулей, и обычный поиск дешевле |

### 7.3. Стоит рассмотреть владельцу, но решение не моё

* **Плагин `hookify`** (официальный маркетплейс `claude-code-plugins`, проверено по
  [его манифесту](https://github.com/anthropics/claude-code/blob/main/.claude-plugin/marketplace.json) — 13 плагинов) — делает хук из описанного правила.
  Метод проекта ровно такой: правило, которое нарушено дважды, переводится в хук. Сейчас
  хуки писались руками.
* **Плагины `code-review` и `pr-review-toolkit`** оттуда же — внешний критический разбор
  здесь уже дал больше находок, чем любой гейт (`docs/audit/critical-review-2026-08-04.md`).
  Оба дублируют встроенный обзор Claude Code, поэтому это выбор, а не рекомендация.
* **Канал Telegram** (`claude-plugins-official`, плагин `telegram`) — владелец получает
  вердикт `/check` туда, где и так читает сигналы бота на `aiogram`.
* **Свой MCP для леджера вместо чужого.** Навык `mcp-builder` в аккаунте уже включён, а
  сервер на чтение поверх `data/ledger.sqlite3` — это десятки строк. Тогда владелец
  спрашивает леджер словами, а §10.2 не нарушается: соединение открывается только на
  чтение, как это уже делает команда `/ledger`.

## 8. Чего эта настройка не делает

* **Chat и Cowork не защищены.** `disableClaudeAiConnectors` действует в сессиях Code.
  В чате Crypto.com остаётся доступен, пока владелец не отключит его в Customize.
* **Файл разработчика не под гейтом.** Он лежит вне репозитория, и проверить его отсюда
  нечем. Пустым его держит только договорённость из §4.
* **Список ключей стареет.** Claude Code добавляет ключи; новый будет объявлен
  неизвестным, пока файл не перевыпущен командой, записанной в его шапке. Это ложный
  минус — заметный и дешёвый; молча проигнорированная настройка дешёвой не бывает.
* **Симлинк `.venv` на Windows.** Создание симлинков там требует режима разработчика или
  прав администратора. Если рабочая копия сессии окажется без `.venv` — это не поломка
  настройки, а отказ прав; `uv sync` в копии решает, ценой пересборки окружения.
