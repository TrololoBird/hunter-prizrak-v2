# E-volume-in-selection — сила по объёму в отборе уровней

Приказ владельца: **«примени силу по объёму в отборе уровней»**.
Основание метода — стр. 22 курса: «Сила уровня определяется ТФ и объемом».
До правки отбор в боте знал только ТФ; объём в него не входил вовсе.

## Отпечаток данных (обязателен, CLAUDE.md — замер по растущему кэшу)

Замеры ниже сняты 2026-08-19 на этом состоянии, и та же команда даст другое число
после первой же доливки данных:

| что | значение на момент замера |
|---|---|
| прогон | `last` — 5 символов: ASTR, BCH, BTC, ETH, POL (все `_USDT_USDT`) |
| кадров на символ | 6 ТФ |
| строк сохранённых карточек | 68 060 (12 712 / 14 094 / 13 944 / 13 552 / 13 758) |
| уровней в леджере | 49 755, из них активных 5 177 |
| сигналов в леджере | 1 425 |
| схема леджера | `schema_version` = **7**, 17 колонок в `levels` — колонки `vrvp_density` в БОЕВОЙ базе ЕЩЁ НЕТ |
| уровней в разборе меры | 9 715 (все уровни всех структур, а не только активные) |

⚠ Строка про схему 7 — не недосмотр, а проверенное состояние. Миграция 7→8 живёт в
`open_production_ledger` (писатель) и сработает при следующем прогоне; бот и `check`
открывают базу `mode=ro` и мигрировать не могут по построению. Поэтому читатель
спрашивает схему через `store.level_columns(conn)` и на схеме 7 подставляет `0`.
Проверено живым чтением боевой базы: 2154 зоны, падения нет, значений силы 0;
на копии, мигрированной до 8, — 274 зоны со значением, максимум 12.5.

## ⚠ Первая редакция меры ОТОЗВАНА: «сила по объёму» оказалась шириной зоны

Сначала силой была ДОЛЯ композита (`vrvp_share` = объём зоны / объём композита × 100).
Дефект нашёлся ГЛАЗАМИ по сообщению бота: у BCH зона 1Д 180.61…250.05 при цене 203.49
несла 49.8% композита — то есть «самым сильным» объявлялся просто самый широкий кусок
шкалы.

| мера | ранговая корреляция с шириной зоны |
|---|---|
| доля композита (`vrvp_share`) | **+0.716** |
| контроль — та же выборка, мера плотности | −0.107 |
| плотность (`vrvp_density`) после замены | **−0.113** |

Ширины топ-20 по доле: 4.5–32.2% цены при медиане 0.6% — доля насыщалась шириной, а не
объёмом. Правился РАСЧЁТ, а не результат: мера заменена на **плотность** — объём на одну
ценовую строку профиля против средней строки композита. 1.0 = «ничем не выделяется».

Следствие на том же BCH: гигантская зона 1Д упала с «сильнейшей» (50% композита) до
×2.9 — слабейшей из пяти, а узкая зона 4ч поднялась до ×6.4 и стала сильнейшей.

## Где отбор решает на самом деле (разбор нуля, а не объяснение)

Первый замер эффекта дал **ноль** («отбор выбрал другое: 0») при пройденном контроле.
Ноль разобран по шагам, а не списан на правдоподобие:

| шаг воронки | уровней |
|---|---|
| всего в леджере | 9 715 |
| активных | 376 |
| прошли `near_structure` (структура ближе 180 баров своего ТФ) | 36 |
| после первого прохода дедупликации | 34 |
| после второго | 31 |

Объёму не на чем было сказаться: дедупликация снимает 5 уровней из 36, а ничьих по ТФ
в этой выборке **0** — то есть ключ отбора решался ТФ ещё до объёма. Настоящий отсев —
`near_structure`: 340 активных уровней из 376 не показываются вовсе.

Отсюда вторая часть правки: **скрытые, но более сильные уровни теперь НАЗЫВАЮТСЯ.**
С плотностью таких нашлось 18 в 3 символах из 5 — раньше они молчали.

## Чем измерено (команды воспроизведения)

Все приборы читают боевую базу ТОЛЬКО `mode=ro` и ничего не пишут в проект.

```bash
# 1. выгрузить зоны из сохранённых кадров (≈10 мин: decide ≈112 с на символ)
uv run python docs/audit/evidence/E-volume-in-selection-2026-08-19/dump_zones.py /tmp/zones.json

# 2. мера и её контроль: корреляция силы с шириной зоны
uv run python docs/audit/evidence/E-volume-in-selection-2026-08-19/analyze_density.py /tmp/zones.json

# 3. воронка отбора и сколько раз у объёма был голос
uv run python docs/audit/evidence/E-volume-in-selection-2026-08-19/analyze_pick.py /tmp/zones.json

# 4. скрытые уровни сильнее показанных
uv run python docs/audit/evidence/E-volume-in-selection-2026-08-19/analyze_hidden.py /tmp/zones.json

# 5. мера С АРТЕФАКТА — по ТЕКСТУ сообщения бота, который читает владелец
uv run python docs/audit/evidence/E-volume-in-selection-2026-08-19/probe_volume_pick.py
uv run python docs/audit/evidence/E-volume-in-selection-2026-08-19/analyze_text.py
```

`tg_zone_widths.py` — прибор ширин зон по тексту бота (v2: v1 считала мусором «зона 4ч»
и порядковые «зона 1 :»).

## Что осталось непроверенным

* эффект отбора замерен на 5 символах прогона `last`, а не на всей вселенной (25);
* плотность посчитана у уровней, где известны обе величины и число строк профиля;
  у уровней без профильного ряда она `None`, и такой уровень в отборе идёт с нулём —
  то есть проигрывает любому посчитанному. Сколько таких на широкой выборке, НЕ ЗАМЕРЕНО;
* порог «называть скрытый уровень» взят 1.2 к среднему — это выбор, не замер;
* дифф повтора §10.6 по этой правке снят ОТДЕЛЬНО и содержит СУММУ правок смены
  (окно композита, `first_verdict`, перенос строки силы в карточке, плотность),
  а не одну только плотность.
