# E-flipped-hidden — целый торгуемый класс уровней исчезал из сообщения молча

Дата: 2026-08-19. Найдено по долгу №2 из
[`docs/audit/session-handoff-2026-08-19.md`](../../session-handoff-2026-08-19.md),
но при проверке оказалось ШИРЕ названного там: не 118 уровней, а весь класс `flipped`.

## Что было

`tgbot.live_unique` начинался строкой `alive = [z for z in zones if z.state == "active"]`.
Запрос `read_map` при этом отдаёт и снятые уровни — они нужны значкам на графике. То есть
пробитые уровни доезжали до сводки и там отбрасывались, не оставив следа.

Курс их торгует прямо, стр. 43: «Уровень лонг/шорт менятся для нас на противоположный.
По возврату цены на ретест уровня -  открываем позицию и ставим СТОП за накопление».
Расчёт это знает и пишет `entry_rule=retest_flipped`; карточка такой уровень печатает
строкой «вход: по ретесту с обратной стороны, в другую сторону (стр. 43)». Бот не
печатал даже их числа.

⚠ Тот же модуль двумя абзацами выше требует обратного для ДВУХ других скрытых классов:
«сводка обязана назвать их числом, а не растворить». Правило было записано и не
применено к третьему классу — это и есть находка.

## Что стало

`live_unique` возвращает четвёртый список, сводка называет его числом:

```
⚙ 124 слились с соседями по зоне · 259 пробитых не в списке — по стр. 43 они торгуются ретестом с обратной стороны
```

Число — ПОСЛЕ той же склейки, что у показанных уровней (`_dedupe`, вынесена из
`live_unique` этой же правкой). Сырых пробитых у структуры 973, разных 259: называть
973 значило бы соврать в другую сторону — столько строк читатель не увидел бы никогда.

## Почему СПИСКОМ они не показаны

Замер, а не осторожность. На боевом леджере 2026-08-19: пробитых **20374** против
**5177** активных. Впуск их со сменой стороны (стр. 43) поднимает перечень:

Сообщение и без того режется по пределу Telegram. КАК отбирать пробитые — решение о
целях, оно владельца. Молчание о них решением не было вовсе, и оно устранено.

## Контроли правки

`probe_note.py` печатает три:

1. **строка появляется**, когда пробитые есть — иначе правка не работает;
2. **строки нет**, когда из карты убраны все `flipped` — иначе прибор печатает
   безусловно, а безусловная печать уже один раз соврала в этом проекте;
3. **подсаженный один** пробитый считается как один — прибор не заперт на большом числе.

Отпечаток данных: `levels` 49755 строк, активных 5177, пробитых 20374; карта BTC —
2229 зон в окне запроса.

## Воспроизведение

```bash
uv run python docs/audit/evidence/E-flipped-hidden-2026-08-19/probe_flipped.py
```

```bash
uv run python docs/audit/evidence/E-flipped-hidden-2026-08-19/probe_note.py
```

Оба читают боевой леджер ТОЛЬКО НА ЧТЕНИЕ и сводят часы нулевым сдвигом (§6 требует
сведения, а зонд к бирже не ходит). Ни один ничего не пишет и в канал не отправляет.

## Что осталось непроверенным

* **дифф повтора §10.6 к этой правке неприменим**: карточка `tgbot` не использует.
  Проверено суммой строк повтора — 68297 до правки и 68297 после, посимвольно та же;
* **живым прогоном не подтверждено**: служба идёт на коде от 17.08 и перезапускается
  только по приказу владельца. Замер снят с боевого леджера и настоящих функций бота,
  но не с отправленного сообщения;
* сторона пробитого уровня в сводке НЕ переворачивается — он туда и не попадает
  списком. Если владелец решит показывать, переворот стороны по стр. 43 обязателен:
  без него флипнутый лонг встанет в блок покупок, то есть на неторгуемую сторону.
