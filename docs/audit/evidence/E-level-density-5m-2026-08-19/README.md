# E-level-density-5m — почему встречный уровень на 5м так близко

Дата: 2026-08-19. Разбор в журнале смены:
[`docs/audit/session-2026-08-17-auto.md`](../../session-2026-08-17-auto.md),
раздел «Плотность уровней на 5м».

## Отозвано этой папкой

**Гипотеза «карта много раз пишет один и тот же физический уровень» — ОПРОВЕРГНУТА.**
Она была моей и выглядела правдоподобно: 3071 активный уровень на 5м против 79 на 1Д,
цель в 0.37% от входа. Опровергла её собственная контрольная опора — расстановка тех же
зон случайными центрами даёт почти ту же кратность склейки. Значит склейка меряет
тесноту ценовой оси, а не повтор уровня.

## Отпечаток данных на момент замера

`data/ledger.sqlite3`: строк в `levels` **49755**, активных **5177**
(5м 3071, 15м 1285, 1ч 503, 4ч 230, 1Д 79, 1Н 9).
Карточки: прогон `last`, **5 символов** (ASTR, BCH, BTC, ETH, POL), **9715** строк уровней.

⚠ Леджер РАСТЁТ. Команды ниже воспроизводят числа только до первой доливки данных;
при расхождении сверяйте отпечаток, который каждый зонд печатает первой строкой.

## Что чем меряется

| зонд | вопрос | контроль |
|---|---|---|
| `probe_level_density.py` | сколько РАЗНЫХ уровней стоит за активными | те же ширины зон со случайными центрами (три посева); плюс разброс по ТФ от 1.12 до 2.30 |
| `probe_structure_height.py` | как запас стопа 1-3% соотносится с высотой базы | монотонность по ТФ (доля структур выше 3%: 7.4 → 100.0) |
| `probe_card_tf_mix.py` | из чего состоит то, что ЧИТАЕТ ВЛАДЕЛЕЦ | сходимость: «без сделки» + «со сделкой» = уровней, расхождение печатается |

Случайность в первом зонде — свой линейный конгруэнтный генератор, а не `random`:
модуль запрещён правилом детерминизма, и запрет здесь по делу — контроль обязан
воспроизводиться посимвольно на чужой машине.

## Итог тремя строками

1. дубликатов нет: кратность 2.30 против 2.14 у случайной опоры, а на 1ч и 1Д настоящие
   уровни разнесены ЛУЧШЕ случайного;
2. причина близкой цели — арифметика курса: запас стопа 3% от цены есть 3.3 высоты базы
   на 5м и пятая часть высоты на 1Д. Дефекта расчёта здесь нет;
3. попутная находка: со стр. 48 в проект взято одно предложение из трёх. Требование
   равновесия состава по ТФ не исполнено — младшие ТФ дают 92.1% карты и 70.2% сделок.

## Что осталось непроверенным

* **равновесие по стр. 48 не введено намеренно** — квота есть фильтр на выходе, а числа
  «баланса» курс не называет. Это решение владельца о целях, не моё;
* кластеризация склеивает зоны ОДНОЙ стороны одного символа одного ТФ. Пересечение
  встречных зон закрыто отдельной правкой смены и здесь не меряется;
* «до ближайшего встречного» считается по активным уровням леджера, то есть по
  состоянию на момент замера, а не на момент рождения каждого уровня. Для вопроса
  «насколько близко цель» этого достаточно, для оценки исходов — нет.
