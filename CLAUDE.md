## Полномочия: полные

Владелец подтвердил многократно (последний раз 2026-08-03):
**можно устанавливать, скачивать и использовать ВСЕ необходимые ресурсы** — пакеты
Python, системные утилиты, MCP-инструменты, отрендеренные артефакты. Разрешение
постоянное, спрашивать заново не нужно.

Отсюда следует главное: **нехватка инструмента — не блокер, а невыполненная работа.**
Строка «X не установлен, поэтому Y не сделано» запрещена. Ставим X и делаем Y; в отчёте
это «поставил X, чтобы сделать Y», и место этой строки — в сделанном, а не в «что
осталось непроверенным».

В блокеры идёт только то, что не решается правами и установкой:
* решение владельца (пример: тикер RES);
* внешний отказ (пример: Binance отдаёт раннерам GitHub `HTTP 451`).

**Граница.** Инструмент для чтения, замера или рендера ставится свободно и в боевой
`pyproject.toml` не попадает — только в группу `tools`/`gates`. Новая зависимость
БОЕВОГО стека — по-прежнему решение по §10 FOUNDATION.

## Число не докладывается, пока не проверено, что оно могло быть другим

Правило введено 2026-08-04 после того, как результат «истинных переприоров ноль» был
подан как утверждение, а оказался артефактом порядка вычислений.

**Перед тем как назвать замер результатом, обязателен контроль: способен ли прибор выдать
ИНОЙ ответ.** Ответ, которого код выдать не может, — свойство кода, а не рынка.

Форма у всех дефектов этого проекта одна, и она узнаваемая:

| что напечаталось | чем оказалось |
|---|---|
| 0% сходящихся структур | зонд считал по точкам, которые детектор не принимает по построению |
| 0 истинных переприоров | признак брался по последним свингам ряда, а не на момент слома |
| 435 пробоев на 4 уровня | контракт «все события» вместо «первое разрешение» |
| «нарушений 0» у гейта чистоты | гейт не открыл ни одного из проверяемых файлов |
| 316 баров тишины | структура не закрывалась, и `detect` об этом молчал |
| `no_priority` 860 из 860 | контрольный скрипт считал старшие ТФ позже младших |

Практически: для каждого исхода — сколько раз он сработал на широкой выборке; для гейта —
пробник с заведомым нарушением и проверка кода возврата; для нуля — разбор по шагам, а НЕ
правдоподобное объяснение. **Ноль с красивой причиной опаснее всего: он не выглядит
дефектом.** Такое объяснение я один раз уже придумал, и оно было связным и неверным.

⚠ Контроль показывает, что прибор не заперт в одном ответе. Он НЕ показывает, что число
верно: отвечающий прибор может быть откалиброван неправильно.

Свод: [`docs/audit/falsifiability-2026-08-04.md`](docs/audit/falsifiability-2026-08-04.md)

## Проверка

```bash
uv run python -m hunter check                        # живое состояние, вердикт по-русски (§7.5)
uv run python -m hunter replay --run-id last --diff  # что изменилось в РАСЧЁТЕ (§10.6 №2)
for g in gates/*.py; do uv run python "$g" || echo "ПРОВАЛ $g"; done
```

**Любое изменение расчёта предъявляется владельцу диффом повтора** — это §10.6 условие 2 и
единственная проверка, не требующая чтения кода. Порядок: `run` сохраняет кадры и
порождённую ими карточку → расчёт меняется → `replay` строит карточку из ТЕХ ЖЕ кадров и
печатает разницу. Карточка обязана быть детерминированной: никаких множеств, словарей в
случайном порядке и отметок времени. Первый же повтор поймал нарушение этого правила —
порядок ТФ наследовался от вызывающего (`docs/audit/replay-2026-08-04.md`).

⚠ Сводка о прогоне гейтов обязана печатать ЧИСЛО и падать по коду возврата. Строка
«гейты зелёные», напечатанная безусловно, уже один раз соврала (2026-08-03).
