# Контроль фальсифицируемости

Правило проекта (CLAUDE.md, раздел «Число не докладывается, пока не проверено, что оно
могло быть другим»): **ответ, которого код выдать не может, — свойство кода, а не
рынка.** Ноль с красивой причиной опаснее всего: он не выглядит дефектом.

Разбор всех известных случаев: [`docs/audit/falsifiability-2026-08-04.md`](../../../docs/audit/falsifiability-2026-08-04.md)

## Три контроля. Пропуск любого — число не докладывается

### 1. Способен ли прибор ответить иначе

Подсади заведомое нарушение и убедись, что оно поймано, потом восстанови и убедись, что
чисто. Обе стороны обязательны: только «поймано» не отличает работающий гейт от гейта,
который ругается всегда.

```bash
# форма контроля: нарушение → код 2/1 с названной причиной; восстановлено → код 0
uv run --group gates python gates/<имя>.py; echo "код возврата: $?"
```

Для замера по данным — прогон на ряде с ЗАРАНЕЕ известным ответом. Если такого ряда
нет, его надо сделать, а не заменить рассуждением о том, почему ответ правдоподобен.

### 2. Не лучше ли случайного — для всякого «совпало N из M»

Прибор, который отвечает по-разному, контроль №1 проходит и всё равно может ничего не
измерять. Проверка: **тот же замер на данных, про которые заведомо известно, что
совпадать они не должны.**

* решётка равноотстоящих (произвольных) цен вместо разметки автора;
* сдвиг всей разметки на k% — совпадения обязаны рассыпаться;
* перемешанный порядок баров там, где порядок должен быть значим.

«Сошлось 20 из 36» превращается в находку, только если на подложных данных сходится
заметно меньше. Иначе это не результат, а плотность точек.

### 3. Сводка отказов по измерению, а не поштучно

Честная деградация ПОШТУЧНО скрывает систематический перекос В СОВОКУПНОСТИ: сто
отказов `NotReady`, все на одном таймфрейме, читаются как «рынок такой», хотя это
дефект сбора. Разбор: [`docs/audit/backfill-window-2026-08-04.md`](../../../docs/audit/backfill-window-2026-08-04.md)

Для каждого набора отказов печатай разрез вдоль измерения, по которому возможен
перекос: таймфрейм, символ, дата, стадия конвейера. Один отказ — данные; сто отказов на
одной оси — находка.

## Что докладывать вместе с числом

* охват — сколько всего проверено, а не только сколько найдено («битых 0» без числа
  проверенных неотличимо от «ничего не смотрели»);
* команду воспроизведения (FOUNDATION §7.3: число без команды не фиксируется);
* результат контроля из п.1 — обе стороны, с кодами возврата;
* для «совпало N из M» — результат контроля из п.2.

## Чего контроль НЕ доказывает

Он показывает, что прибор не заперт в одном ответе. Он **не** показывает, что число
верно: отвечающий прибор может быть откалиброван неправильно. Формулировка в отчёте —
«контроль пройден», а не «число подтверждено».

## Признаки, по которым контроль обязателен немедленно

* ровный ноль, стопроцентное совпадение, «все» или «ни одного»;
* число, полученное после правки расчёта, но совпавшее с прежним до цифры;
* сводка, напечатанная безусловно («гейты зелёные» без кода возврата);
* доля, посчитанная по выборке, которую сам же детектор и отобрал.

## Каталог уже случившихся форм

Перенесено сюда из `CLAUDE.md` 2026-08-23: правило осталось там, а каталог примеров живёт
здесь и грузится вместе с этим навыком — то есть ровно тогда, когда в ответ идёт число.
Форма у всех дефектов этого проекта одна, и она узнаваемая:

| что напечаталось | чем оказалось |
|---|---|
| 0% сходящихся структур | зонд считал по точкам, которые детектор не принимает по построению |
| 0 истинных переприоров | признак брался по последним свингам ряда, а не на момент слома |
| 435 пробоев на 4 уровня | контракт «все события» вместо «первое разрешение» |
| «нарушений 0» у гейта чистоты | гейт не открыл ни одного из проверяемых файлов |
| 316 баров тишины | структура не закрывалась, и детектор об этом молчал |
| `no_priority` 860 из 860 | контрольный скрипт считал старшие ТФ позже младших |
| «сошлось 20 из 36 уровней автора» | решётка ПРОИЗВОЛЬНЫХ цен сходилась не хуже: ПОК было вчетверо больше, чем нужно |
| «средний R = +0.17 по журналу» | исход досчитывался только у сигналов, чей уровень ЕЩЁ отбирается: две трети журнала (76 из 112) ответа не получали никогда |
| «гейт геометрии: нарушений 0» | гейт сторожил коробку `range_*`, а карточка печатала линии `boundary_*`: проверялась НЕ ТА величина, которую видит владелец |
| «стоп 0.3% от входа» | стоп считался от линии свингов, которую карточка звала «границей»; за коробку структуры он не выходил вовсе |
| «487 строк капслоком из 653» | `grep -E "[А-ЯЁ]{8,}"` в этой среде матчит БАЙТЫ, а не буквы; правильный ответ — 70 |

⚠ Строка про «средний R» — форма опаснее прочих: прибор ОТВЕЧАЛ по-разному, то есть
контроль №1 проходил. Сломался следующий уровень — **ответ был не лучше случайного**.
Именно отсюда взялся контроль №2.

⚠⚠ **Честная деградация ПОШТУЧНО скрывает систематический перекос В СОВОКУПНОСТИ.**
Бэкфилл качал «последние 3 суток», и каждый непостроенный уровень честно сообщал
`NotReady`. Но никто не сложил отказы ПО ТАЙМФРЕЙМУ: уровень получали 15% структур, а на
4ч и 1Д — ноль из 28 и 21, то есть карта состояла ровно из тех ТФ, которые курс считает
слабее. Сто девяносто честных отказов подряд читаются как «рынок такой».

⚠⚠ **Всякая накопленная статистика обязана называть, по какой ПОДВЫБОРКЕ она посчитана.**
Сводка `store.outcome_survey` (тип × ТФ × сторона) показала клетку «6 сигналов, 1647
прожитых баров, ноль исходов». Правдоподобная причина («символы не участвовали в
прогоне») ПРОВЕРЕНА И ОПРОВЕРГНУТА; настоящая — исход досчитывался только у сигналов,
которые прогон эмитирует ЗАНОВО.

⚠⚠ **Остаток после правки разбирается, а не списывается на шум.** 2026-08-18 слияние
границ убрало вылезание зоны за базу с 51.7% до 0.7% — 68 случаев из 9715. Хвост в
полпроцента читался как «рынок такой», а оказался арифметикой прибора: сетка профиля
квантуется тиками, число строк берётся вверх, и верх последней строки торчит выше
диапазона. **Пока механизм остатка не НАЗВАН на разобранном примере, правка не
завершена.** Правдоподобие остатка — тот же дефект, что правдоподобие нуля, только его
защищает малость числа: 0.7% никто не идёт проверять.
